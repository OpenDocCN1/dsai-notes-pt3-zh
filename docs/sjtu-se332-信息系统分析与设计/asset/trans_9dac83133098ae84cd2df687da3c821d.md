## 2 基于EPC的过程建模方法

EPC 是一种过程建模方法，全称是Event-driven Process Chain。在九十年代初期才由Keller 等人提出，强调“过程”是由起始事件和终止事件定义的。

事件过程链（EPC）模型借鉴了ER模型和DFD建立，基本元素有事件、过程，分支/规则等。

被广泛应用：

- SAP R/3 Business Workflow (SAP AG),
- ARIS (IDS Prof. Scheer),
- LiveModel/Analyst (Intellicorp, Inc.)

- 在EPC出现之前，其他描述业务组织和过程的方法都太复杂了。
- 它们既不能提供并行过程的链接，也不会提供诸如组织或信息流视图这样的观察角度。
- 其他的方法也过于面向IT，或者使用了太复杂的符号。
- 另一方面，EPC方法从用户、管理人员和咨询顾问的角度出发描绘了业务信息系统，同时加入了其他一些重要特征，如组织结构、功能、数据和信息流。利用实际业务经验和易于理解的符号和语言。

### Concept

功能是为达到一个或多个企业目标而作用在（信息）对象上的一个任务，操作或活动。

一个功能可以由时间和成本来定义特性。

### 2.2 EPC基本语义

Functions: 过程的活动

Events: 功能的先决条件和后置条件

- EPC Function
- EPC Event
- XOR Split: 定义一个选择以激活多个后续分支中的一个。
- AND Split: 并发激活所有后续分支。
- OR Split: 触发一个、两个或多个后续分支中的全部。
- XOR Join: 当其中一个备选分支完成后继续。
- AND Join: 等待所有传入分支完成。
- OR Join: 等待所有活动分支完成。

### 2.3 Rules

- Rule1: EPC模型必须以事件开始；
- Rule2: EPC模型必须以事件结束；
- Rule3: 功能和事件应交替出现；
- Rule4: 连接功能和事件时，此类节点只能有一个输入和一个输出；
- Rule5: 事件是一个被动元素，没有任何决策能力！
  - 该规则主要影响逻辑运算符的使用以及基于此连接的功能和事件的连接。

### Rules for Branches

不要在事件后使用 OR / XOR！！

### EPC 和 PetriNet 的转换

- Event 可以映射为PN 中的库所（Place）
- Function 可以映射为PN 中的变迁（Transition）。
- 至于逻辑连接符AND 和XOR 的映射，在采用Place的控制下，很容易表示。
- 因为OR 的语义有多种诠释，不是非常清晰明确，因此不涉及到对OR逻辑连接符的映射。
