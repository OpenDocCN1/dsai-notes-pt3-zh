## 贝叶斯网络的LPMLN编码 🔗

上一节我们介绍了LPMLN语言。本节中，我们来看看如何将贝叶斯网络编码到LPMLN中。

![](img/2d20db5ca31f8396097efc58ff761498_7.png)

![](img/2d20db5ca31f8396097efc58ff761498_9.png)

一个贝叶斯网络可以方便地用LPMLN语言编码。你可以使用LGM-into-ESP系统（我们将在本课讨论其原理）进行计算。该系统将LPMLN语言翻译成ASP语言，从而可以使用Clingo来计算LPMLN程序。从用户的角度来看，他们不需要了解底层的ASP语言，可以将其视为LPMLN求解器。

![](img/2d20db5ca31f8396097efc58ff761498_11.png)

以下是编码的核心步骤：

1.  **定义概率分布**：给定条件概率表，我们可以将其编码为事实。例如，如果“篡改”为真的概率是0.02，我们可以写为：
    ```
    w : tempering.
    ```
    其中权重 `w` 是 `log(p/(1-p))`。当这个事实被选中时，其权重为 `e^w = p/(1-p)`；如果未被选中，则权重为1。经过归一化后，该事实为真的概率就是 `p`。

![](img/2d20db5ca31f8396097efc58ff761498_13.png)

2.  **编码依赖关系**：网络中的边（依赖关系）可以用规则表示。例如，父节点在规则体部，子节点在规则头部。
    ```
    w : alarm :- tempering.
    ```
    在更一般的情况下，例如“警报”在“篡改”和“火灾”都为真时触发，你需要为所有父节点状态的组合编写规则。本质上，一条边（或一个条件概率表）可以表示为多条规则。

3.  **进行概率查询**：要计算在给定证据下的条件概率，例如已知“警报”和“篡改”为真时“火灾”的概率，我们将证据作为事实加入程序，然后使用系统命令行进行查询。查询可以针对不同的变量进行，实现因果、诊断等各类推理。

同一个贝叶斯网络也可以用不同的LPMLN实现来表示，例如“LPMLN-to-MLN”。顾名思义，我们可以将LPMLN语言转换为马尔可夫逻辑网络，从而使用Alchemy进行计算。其输入语言与Alchemy类似，但规则使用 `:-` 符号表示蕴含，合取使用 `&` 符号。

![](img/2d20db5ca31f8396097efc58ff761498_15.png)

## 从ASP到LPMLN ➡️

![](img/2d20db5ca31f8396097efc58ff761498_17.png)

![](img/2d20db5ca31f8396097efc58ff761498_19.png)

本节我们来看看如何将ASP程序视为LPMLN的特例。

![](img/2d20db5ca31f8396097efc58ff761498_21.png)

![](img/2d20db5ca31f8396097efc58ff761498_23.png)

![](img/2d20db5ca31f8396097efc58ff761498_25.png)

一个ASP程序可以被看作是LPMLN的一个特例，只需为每条规则分配无限大的权重（`α`）。具体来说，对于任何ASP程序 `π`，其确定性稳定模型恰好是转换后LPMLN程序 `π^α` 的概率为1的稳定模型。在这些稳定模型中，只有那些使用了程序中所有规则的模型（其权重为 `e^(kα)`，`k` 是规则总数）才对应原ASP程序的答案集。

![](img/2d20db5ca31f8396097efc58ff761498_27.png)

**关键点**：如果原ASP程序至少有一个稳定模型（即是一致的），那么转换后LPMLN程序中所有非零概率的稳定模型都具有相同的概率，并且它们就是原ASP程序的稳定模型。如果原程序没有稳定模型，这种对应关系则不成立。

![](img/2d20db5ca31f8396097efc58ff761498_29.png)

![](img/2d20db5ca31f8396097efc58ff761498_31.png)

## 从马尔可夫逻辑到LPMLN ➡️

本节我们探讨如何将马尔可夫逻辑网络嵌入到LPMLN中。

![](img/2d20db5ca31f8396097efc58ff761498_33.png)

将马尔可夫逻辑网络转换为LPMLN相对直观。其思想类似于将命题逻辑公式转换为ASP程序以生成其所有模型。转换方法如下：

![](img/2d20db5ca31f8396097efc58ff761498_35.png)

![](img/2d20db5ca31f8396097efc58ff761498_37.png)

![](img/2d20db5ca31f8396097efc58ff761498_39.png)

1.  保留原MLN中的所有加权公式。
2.  为所有原子添加选择规则，形式为 `{A}.`，并为这些选择规则分配任意权重。

![](img/2d20db5ca31f8396097efc58ff761498_40.png)

![](img/2d20db5ca31f8396097efc58ff761498_42.png)

**定理**：通过这种转换，任何MLN程序与其LPMLN对应程序在所有解释上具有相同的概率分布。添加选择规则的效果是使原子在稳定模型语义下免于最小化，从而能够表示所有可能的模型。

## 从LPMLN到马尔可夫逻辑（紧致程序）🔄

本节我们学习一种称为“完成”的经典技术，可将特定类型的LPMLN程序转换回马尔可夫逻辑。

“完成”是一种将ASP程序转化为命题逻辑公式的技术。对于满足特定条件的“紧致”ASP程序，其稳定模型恰好是其完成公式的经典模型。

**紧致程序的定义**：一个程序是紧致的，如果其依赖图（从规则头部指向体部正原子的边构成的有向图）中不包含循环。

**完成过程**（针对头部为单个原子的规则）：
1.  对于每个原子 `A`，收集所有以 `A` 为头部的规则体 `Body_i`。
2.  为 `A` 创建完成公式：`A <=> (Body_1 ∨ Body_2 ∨ ... ∨ Body_n)`。
3.  整个程序的完成是所有原子完成公式的合取。

![](img/2d20db5ca31f8396097efc58ff761498_44.png)

**转换LPMLN到MLN**：对于一个由紧致规则组成的LPMLN程序，我们可以将其每条规则和每个完成公式都视为MLN中的公式，并为完成公式分配无限大权重（`α`）。这样，原LPMLN程序的概率信息就由规则权重携带，而完成公式确保了语义的一致性。

## 总结 📝

本节课中我们一起学习了不同知识表征形式化语言（ASP、马尔可夫逻辑、LPMLN）之间的相互转换。

![](img/2d20db5ca31f8396097efc58ff761498_46.png)

*   我们看到了LPMLN如何作为ASP和马尔可夫逻辑的泛化，并能对二者进行编码。
*   我们学习了如何通过分配无限权重，将ASP程序转换为LPMLN程序。
*   我们了解了通过添加选择规则，可以将马尔可夫逻辑网络转换为LPMLN程序。
*   我们探讨了使用“完成”技术，将特定类型（紧致）的LPMLN程序转换回马尔可夫逻辑网络，从而利用Alchemy等求解器进行计算。

这些转换揭示了不同语言之间的内在联系，并允许我们利用一种语言的高效求解器来解决另一种语言的问题。在实际应用中，可以根据要建模的知识特点选择最合适的语言，然后在底层利用转换和现有的求解器进行计算。对于非紧致的LPMLN程序，可以将其转换为ASP程序来处理，这将是我们下节课的内容。
