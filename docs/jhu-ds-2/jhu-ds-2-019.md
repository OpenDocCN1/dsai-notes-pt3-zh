# 019：读取大型表格 📊

![](img/0a3b4ddab3e203a4c5725aa096c9840f_0.png)

在本节课中，我们将学习如何高效地读取大型数据集到R中。处理超出中小型规模的数据集时，需要采取一些策略来避免R程序崩溃，并提升读取效率。

## 概述

当处理大型表格数据时，直接使用`read.table`或`read.csv`可能会导致内存不足或速度缓慢。本节将介绍几个关键技巧，帮助你预先评估内存需求并优化读取过程，确保操作顺利进行。

## 优化读取大型表格的策略

上一节我们了解了读取数据的基本方法，本节中我们来看看针对大型数据集的具体优化措施。

首先，你应该仔细阅读`read.table`函数的帮助页面。其中包含了许多关于如何优化读取大型数据集的关键提示和有用信息。

### 关键优化步骤

以下是几个可以显著提升读取效率并避免问题的关键步骤：

1.  **预先计算所需内存**：在读取数据前，粗略计算存储数据所需的内存。这有助于判断你的计算机是否有足够的内存（RAM）来容纳整个数据集，因为R默认会将所有数据读入内存。
2.  **设置`comment.char`参数**：如果你的数据文件中没有注释行，可以将`comment.char`参数设置为空字符串（`""`）。这能避免R去扫描可能的注释符号，从而节省时间。
3.  **指定`colClasses`参数**：这个参数非常重要。如果不指定，R会遍历每一列数据来推断其类型（如数值型、字符型）。对于大型数据集，这个推断过程会消耗大量时间和内存。如果你能提前告知R每一列的数据类型，读取速度会大大加快。
    *   如果所有列都是同一类型（例如全是数值），可以简单地将`colClasses`设置为`"numeric"`。
    *   如果列类型不同，可以先使用`nrows`参数读取前100或1000行，然后用`sapply`函数和`class`函数获取每一列的类型，再将结果向量作为`colClasses`参数的值来读取完整数据集。
4.  **利用`nrows`参数**：指定要读取的行数。这虽然不一定能让R运行得更快，但有助于R更精确地预先分配内存，而不是在读取过程中动态调整。即使略微高估行数也没有关系，R最终只会读取实际存在的行数。

## 处理大型数据前的准备工作

在开始处理大型数据集前，了解一些系统信息会很有帮助。

*   **计算机内存（RAM）大小**：你的电脑有多少物理内存？如今大多数电脑有几GB到数十GB的内存。
*   **其他正在运行的应用程序**：是否有其他程序正在占用处理器时间或内存？如果你在多用户系统上，其他用户是否也在占用资源？
*   **操作系统**：你使用的是Mac、Windows、Unix还是Linux？
*   **操作系统位数**：是32位还是64位？64位系统通常能访问更多内存。

## 如何估算内存需求

让我们通过一个例子来学习如何在实际读取数据前进行快速的内存估算。

假设我们有一个数据框，包含150万行和120列，并且所有列都是数值型数据。

我们需要计算在内存中存储这个数据框大致需要多少空间。

**计算步骤如下：**

1.  计算数据框中的元素总数：`1,500,000 * 120 = 180,000,000`
2.  在R中，每个数值型（numeric）元素占用8字节（8 bytes）内存（因为使用64位浮点数存储）。
3.  因此，总内存需求（字节）为：`180,000,000 * 8 = 1,440,000,000` 字节。
4.  转换为兆字节（MB）：`1,440,000,000 / (2^20) ≈ 1373.29 MB`
5.  转换为千兆字节（GB）：`1373.29 / (2^10) ≈ 1.34 GB`

所以，这个数据框的原始存储需求大约是 **1.34 GB**。

**重要经验法则**：使用`read.table`读取数据时，实际需要的内存大约是数据对象本身大小的**两倍**。因此，读取这个1.34 GB的数据集，你可能需要准备约 **2.68 GB** 的可用内存。

如果你的电脑只有2GB内存，尝试读取这个数据集就会非常吃力，可能因内存不足而失败。但如果你的电脑有4GB、8GB或16GB内存，那么在内存方面应该没有问题（尽管读取本身仍需时间）。
