- 支持度（support）：规则 A→B 在事务集 D 中成立，具有支持度 s，其中 s 是 D 中事务包含 A ∪ B 的百分比。
- 可信度（confidence）：规则 A→B 在 D 中具有可信度 c，即 D 中包含 A 的同时也包含 B 的百分比。
- support(A→B) = P(A ∪ B) = 包含 A 和 B 的事务数 / 事务总数
- confidence(A→B) = P(B | A)
- 包含 k 个项的项集称为 k-项集。
- 项集的出现频率为包含项集的事务数，也称支持计数。
- 频繁项集 $L_k$：项集满足最小支持度，也可利用项集的出现频率。

## 2 挖掘的基本过程

挖掘关联规则就是对给定的一组事务集 D，找出所有满足用户指定的最小支持度（min_sup）和最小置信度（min_conf）的关联规则。关联规则的挖掘可分为两个步骤：

1. 寻找所有频繁项集 $L_k$，即项集的出现频率大于或等于最小支持度与事务集 D 中总数的乘积。
2. 使用频繁项集产生强关联规则。这些规则必须同时满足 min_sup 和 min_conf。

- 连接：对于数据项集 $p, q \in L_{k-1}$，如果它们的前 $k-2$ 项相同，即 $p[1] = q[1]$，……，$p[k-2] = q[k-2]$，$p[k-1] < q[k-1]$，则将 $p \cup q$，即 $p[1]p[2]\dots p[k-1]q[k-1]$ 插入 $C_k$（候选项集）。
- 修剪：对于所有数据项集 $c \in C_k$，如果 $c$ 的某个 $(k-1)$-子集不在 $L_{k-1}$ 中，则将 $c$ 从 $C_k$ 中删除。

## 使用频繁项集产生强关联规则

- 对一个频繁项集 $L_k$，首先产生后项只有一项的所有规则，再产生后项有二项的规则，如此不断反复产生具有更多后项的规则。
- $conf(A \to B) = P(B|A) = \frac{support\_count(A \cup B)}{support\_count(A)}$
- $support\_count(A \cup B)$ 是包含项集 $A \cup B$ 的事务数；$support\_count(A)$ 是包含项集 $A$ 的事务数。

由 $L = \{I1, I2, I5\}$ 可以产生哪些关联规则？设 min_conf = 70%。

- $I1 \land I2 \to I5$：conf = 2/4 = 50%
- $I1 \land I5 \to I2$：conf = 2/2 = 100% √
- $I2 \land I5 \to I1$：conf = 2/2 = 100% √
- $I1 \to I2 \land I5$：conf = 2/6 = 33%
- $I2 \to I1 \land I5$：conf = 2/7 = 29%
- $I5 \to I1 \land I2$：conf = 2/2 = 100% √

令 $L_k$ 为一组频繁项集，$C_k$ 为一组候选 $k$-项集。发现所有频繁项集的算法 Apriori 可描述如下：

输入：数据库 D；最小支持度 min_sup。

输出：D 中的频繁项集 L。

```pseudocode
1)  L1 <- {频繁1-项集};
2)  for (k=2; L_{k-1} != Φ; k++){
3)      C_k = apriori-gen(L_{k-1}, min_sup);
4)      for t = each transaction of D {    // scan D for count
5)          C_t = subset(C_k, t)    // get the subset of t that are candidates
6)          for c = each candidate of C_t
7)              c.count++}
8)      L_k = {c ∈ C_k | c.count ≥ min_sup}
9)  }
10) return L = ∪_k L_k
```
