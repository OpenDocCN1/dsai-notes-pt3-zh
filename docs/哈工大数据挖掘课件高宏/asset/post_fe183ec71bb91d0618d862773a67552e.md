
## 5.1 基本概念

- 项(item)
  - 一个字符串序列，描述一个有意义的对象
- 项集I(itemset): 项的集合
  - I={i1, i2, ......, im}，其中i为一个item。
- 任务相关的数据D是数据库事务(交易)的集合，其中每个事务T是项的集合，使得T⊆I。
  - 每一个事务有一个标识符，称作TID。
- 设A是一个项集，事务T包含A，当且仅当 A⊆ T。

## 5.1 基本概念

- **k-itemset**: 包含 *k* 个项的集合。
  例如：项集{bread, milk}是一个2-项集。
- **项集A的出现频率**(*frequency or support count*)
  包含项集A的事务数
- **频繁项集** *frequent itemset* (大项集 *large itemset*)
  - 如果该项集满足最小支持度 *min_sup*
  - 频繁 *k*-项集的集合通常记作 $L_k$。

## 5.1 基本概念

- 关联规则是形如 A⇒B 的蕴涵式，其中，A ⊂ I, B ⊂ I, 并且 A∩B = ∅。可以表示为：
- A⇒B [s= xx%, c= xx%]

- 规则 A⇒B 在事务集 D 中成立具有支持度 s

- s 为概率 P(A∪B)，即 D 中事务包含 A∪B 的概率。

- 规则 A⇒B 在事务集 D 中成立具有置信度 c

- c 为条件概率 P(B|A)，即 D 中包含 A 的事务同时也包含 B 的概率。

## 5.2 经典关联规则挖掘算法

## priori knowledge推理

- The downward closure property of frequent patterns
  - Any subset of a frequent itemset must be frequent
  - If {beer, diaper, nuts} is frequent, so is {beer, diaper}
  - i.e., every transaction having {beer, diaper, nuts} also contains {beer, diaper}

- Observation
  - 若不是频繁的，则将项A加入后组成的{A} ∪ I也不是频繁的。
  - {milk, eggs,bread}不会比{milk, eggs}更频繁出现

## 5.2.1 Apriori算法

## Apriori 算法

## Main idea

采用逐层搜索的迭代方法，利用*k*-项集探索*k+1*-项集。

- 首先找出频繁1-项集的集合，记作*L₁*。

- 利用*L₁*搜索、查找频繁2-项集的集合*L₂*，

- 而*L₂*用于找*L₃*，

- ……，如此下去，直到不能找到频繁*k*-项集。

找每个*L_j*都需要一次数据库扫描

## Apriori 算法

- *a priori knowledge*推理：
  - 频繁项集的所有非空子集必须也是频繁的
  - 观察
    - 若项集不满足最小支持度 *min_sup*，则不是频繁的，即 P(I) < *min_sup*。
    - 如果项A添加到I中，则结果项集{A} ∪ I 不可能比I更频繁出现。因此，{A} ∪ I 也不是频繁的。

| T2 | Milk | bread | sugar | eggs |
| T3 | milk | bread | butter |  |
| T4 | sugar | eggs |  |  |
| T5 | beer | diaper | cigarette |  |
| T6 | Pen | diaper | chewing gum |  |
| T8 | milk | diaper | beer | eggs |

{milk, eggs,bread}不会比{milk, eggs}更频繁出现
