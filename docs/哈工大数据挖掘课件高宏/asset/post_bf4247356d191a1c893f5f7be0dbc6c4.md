# How about the joinable Lₖ are not ordered and constrained?

- for example, without those constraints, {I1, I3, I5} and {I1, I4, I5} will be joined to {I1, I3, I4, I5}
- however, in Apriori, if {I1, I3, I4, I5} is a frequent itemset, it will be generated from {I1, I3, I4} and {I1, I3, I5}. Otherwise it will not be generated
  - therefore those constraints are useful in generating a relatively small set of candidate frequent itemsets
  - moreover, those constraints can avoid the cost of generating the same candidate frequent itemsets for several times

# Apriori 算法的改进

- Sampling for Frequent Patterns
  - 在原始数据上抽取一组样本，在样本数据上应用 Apriori算法计算频繁项集
  - Scan database once to verify frequent itemsets found in sample, only *borders* of closure of frequent patterns are checked
    - Example: check *abcd* instead of *ab, ac, ..., etc.*
  - Scan database again to find missed frequent patterns
  - H. Toivonen. Sampling large databases for association rules. In *VLDB’96*

- Once both A and D are determined frequent, the counting of AD begins

# Apriori类算法问题

- 瓶颈: candidate-generation-and-test
  - Mining long patterns needs many passes of scanning
  - generates lots of candidates
    - 10⁴ frequent 1-itemset will generate 10⁷ candidate 2-itemsets
    - To find frequent itemset i₁i₂...i₁₀₀
      - # of scans: **100**
      - # of Candidates: \(\binom{100}{1}+\binom{100}{2}+...+\binom{100}{100}=2^{100}-1=1.27*10^{30}!\)

# FP-Growth算法

- Mining Frequent Patterns Without Candidate Generation
- Grow long patterns from short ones using local frequent items
  - “abc” is a frequent pattern
  - Get all transactions having “abc”: DB|abc
  - “d” is a local frequent item in DB|abc → abcd is a frequent pattern
