## 线性处理 vs. 并行处理 ⚖️

要理解并行处理，最好通过与线性处理进行比较。

### 线性处理
线性处理是计算问题的传统方法。问题陈述被分解为一组指令，这些指令按顺序执行，直到所有指令成功完成。

如果任何一条指令出错，在错误解决后，整个指令序列需要从头开始重新执行。

从处理方法可以明显看出，线性处理最适合小型计算任务。在处理复杂问题（如大数据）时，它效率低下且耗时。

**公式表示：**
`线性处理 = 顺序执行(指令1, 指令2, ..., 指令N)`

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_9.png)

### 并行处理
线性处理的替代方案是并行处理。在这里，问题陈述同样被分解为一组可执行指令。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_10.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_11.png)

然后，这些指令被分配到多个具有相同处理能力的执行节点上，并行执行。

由于指令在独立的执行节点上运行，错误可以在本地修复和执行，独立于其他指令。

正如上一节所述，在处理大数据等复杂问题时，并行处理提供了显著优势。

## 并行处理的优势 💪

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_13.png)

使用并行处理的其他好处包括：

**处理时间减少**：与线性处理相比，并行处理能以更短的时间处理大数据。

**内存和处理需求低**：由于问题指令在独立的执行节点上执行，即使在处理海量数据时，内存和处理需求也较低。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_15.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_16.png)

**灵活性**：并行处理的最大优势是可以根据需要随时添加或移除执行节点。这显著降低了基础设施成本。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_17.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_18.png)

## 数据扩展策略：纵向扩展 vs. 水平扩展 📈

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_20.png)

数据扩展是一种管理、存储和处理数据溢出的技术。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_21.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_22.png)

你可以获得一台更大的单节点计算机。但当你的数据呈指数级增长时，它最终会超出可用容量。

通过增加单个节点的容量来提高能力，这被称为**纵向扩展**。

一个更好的策略，或者说大多数人最终选择的策略，是**水平扩展**或**横向扩展**。这简单地意味着添加具有相同容量的额外节点，直到问题变得可处理。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_24.png)

以这种方式排列的单个节点被称为**计算集群**。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_25.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_26.png)

## 易并行计算 🧩

计算集群可以解决被称为“易并行”计算的问题。

这类工作负载可以轻松地分割并彼此独立运行。如果任何一个进程失败，它不会影响其他进程，并且可以轻松地重新运行。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_28.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_29.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_30.png)

**示例**：更改一个大型数据集中单个列的日期格式，该数据集已被分割成多个较小的块，存储在集群的不同节点上。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_31.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_32.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_33.png)

**代码概念表示：**
```python
# 伪代码：在每个数据分块上独立执行相同操作
for data_chunk in split_large_dataset:
    result = change_date_format(data_chunk['column'])
    save_result(result)
```

## 非易并行计算的复杂性 🔗

有时，对大型数据集进行排序会给流程增加显著的复杂性。

现在，多个计算必须相互协调，因为每个进程都需要了解其对等进程的状态才能完成计算。这需要通过网络相互发送消息，或将它们写入集群上所有进程都可访问的文件系统。

## 企业环境中的并行计算与“将计算移至数据” 🏢

企业环境中的大多数计算被认为是“易并行”的，其中也包含一些不那么容易的计算。

虽然这个说法在不同程度上是正确的，但它指导了底层框架的设计。

在Hadoop生态系统中，“将计算移至数据”是集群设计的核心理念。集群的设计方式是，对数据的某些部分或分区的计算将尽可能在数据所在的位置进行。结果输出也将写入同一节点。

## 并行计算中的容错性 🛡️

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_44.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_45.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_46.png)

计算机会发生故障，你需要做好准备。在这种情况下，容错性就发挥了作用。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_47.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_48.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_49.png)

**容错性**是指系统在一个或多个组件发生故障时继续不间断运行的能力。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_50.png)

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_51.png)

这对于Hadoop的主要数据存储系统HDFS以及其他类似的存储系统（如S3和对象存储）都适用。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_53.png)

考虑一个数据集的前三个分区，标记为P1、P2和P3，它们驻留在第一个节点上。在这个系统中，这些数据分区的副本也存储在集群内的其他位置或节点上。

如果第一个节点宕机，你可以向集群添加一个新节点，并通过从存储有P1、P2和P3分区副本的其他节点之一复制数据来恢复丢失的分区。

显然，这是一个极其复杂的维护过程。但Hadoop文件系统作为一个健壮且经过时间考验的框架，其可靠性可以达到99.999%。

## 总结 📚

本节课中我们一起学习了：

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_55.png)

1.  **大数据需要并行处理**，因为海量数据太大，无法容纳在任何一台计算机上。
2.  **线性处理是顺序的**，而**并行处理**同时处理多个指令。
3.  与线性处理相比，并行处理具有显著优势，最适合处理大数据。
4.  大数据中的并行化是在并行计算环境中跨多个处理器进行的，重点在于将数据分布到不同的节点上并行操作。
5.  **水平扩展（横向扩展）** 是一种通过增加节点数量来提高能力的策略。
6.  **易并行计算**是那些可以轻松分割并彼此独立运行的工作负载。如果任何一个进程失败，它不会影响其他进程，并且可以简单地重新运行。
7.  **容错性**是使系统在其某些组件发生故障时能够继续正常运行的属性。

![](img/fcd7b747e445fd3c3bec22ce62bc7fad_57.png)

通过掌握这些核心概念，你为理解和设计高效的大数据处理系统奠定了坚实的基础。
