# 027：撰写有效的少样本示例 🎯

在本节课中，我们将学习如何构建有效的少样本提示。我们将通过分析几个设计不佳的示例，来理解在格式化提示时常见的错误，并从中学习如何改进。

## 概述：为何少样本示例会出错

上一节我们介绍了少样本学习的基本概念。本节中，我们来看看在构建少样本示例时，哪些因素会导致模型困惑或输出错误结果。关键在于确保提示能清晰地向语言模型传达任务意图。

## 示例一：模糊的上下文与任务

首先，我们来看一个设计不佳的提示示例。其目的是让模型分析物体的“硬度”，输出应为“软”或“硬”。

```
输入：砖块
输出：硬

输入：枕头
输出：软

输入：汽车
```

这个提示存在几个问题。首先，示例数量不足。其次，任务上下文非常模糊。“输入”和“输出”是通用前缀，没有向语言模型说明我们具体在描述物体的哪个属性（例如表面触感、材质）。此外，“汽车”的硬度并不像“砖块”和“枕头”那样直观。

当用此提示询问ChatGPT时，它可能回复“快”或“交通工具”。这表明模型无法从给定的模式中确定下一个输出应该是什么。

以下是此提示的主要问题：
*   **前缀信息不足**：“输入/输出”未能提供关于任务性质的任何上下文。
*   **任务描述模糊**：未明确指定我们是在评估物体的“表面感觉”、“材质”还是其他属性。
*   **示例代表性不强**：示例未能清晰界定“软/硬”的分类逻辑。

**改进方法**：我们可以在示例前增加指令，为模型提供明确约束。

```
你的输出只能是“软”或“硬”。
输入：砖块
输出：硬

输入：枕头
输出：软

输入：汽车
```

通过添加指令“你的输出只能是‘软’或‘硬’”，我们限定了输出范围，帮助模型将任务理解为“判断物体的触感硬度”，从而更可能得到正确答案“硬”。

**核心要点**：在编写少样本示例时，需确保你的前缀具有意义，并能提供额外上下文，帮助大语言模型理解序列中的逻辑关系。

## 示例二：输入信息不充分

接下来，我们看另一个关于物体“速度”分类的示例。这个示例的前缀稍好一些。

```
物体：飞机， 速度：快
物体：蠕虫， 速度：慢
物体：球， 速度：？
```

这里，“速度”这个前缀比单纯的“输入”更具描述性。然而，当我们输入“球”时，模型可能输出“可变”。这是因为“球”的速度情境依赖性强（例如，被婴儿踢出 vs. 从炮中射出），输入信息不足以让模型做出明确分类。

**改进方法**：在输入中提供更丰富的上下文。

```
物体：飞机， 速度：快
物体：蠕虫， 速度：慢
物体：被婴儿踢出的球， 速度：慢
```

通过将输入改为“被婴儿踢出的球”，我们提供了足够的情境，模型便能明确地输出“慢”。

## 构建有效少样本提示的要点

基于以上分析，以下是撰写有效少样本示例时需要思考的关键点：

1.  **确保前缀具有描述性**：使用能清晰传达任务属性的前缀（如“速度：”、“硬度：”），而非通用的“输入/输出”。
2.  **示例需包含充分信息**：每个示例都应提供足够的信息，让人或模型能够推导出从输入到输出的底层逻辑或规则。可以自问：如果给10个人看这些例子，他们是否都能毫无歧义地理解你想要什么？
3.  **在示例前提供必要指令**：如果仅靠示例无法清晰传达复杂规则，可以在提示开头添加简要的指令或规则进行补充说明。
4.  **平衡指令与示例**：在有限的提示空间内，需要权衡：某个信息是更适合用一个简明的示例来演示，还是用一句指令来规定？目标是使用更少的词语获得更准确的输出。
5.  **确保新输入信息充足**：即使你通过示例完美地教会了模型某个处理过程，也必须确保新的输入包含了应用该过程所需的全部相关信息。否则，模型将无法进行有效推理。

## 总结

本节课中，我们一起学习了如何诊断和改进少样本提示。关键在于**提供清晰的上下文**、**使用描述性的前缀**、**确保示例信息充足**，并在必要时**用指令补充规则**。通过仔细设计你的少样本示例，你可以更有效地引导大语言模型理解并执行复杂任务。记住，好的提示就像一份清晰的操作手册，能让模型准确无误地工作。
