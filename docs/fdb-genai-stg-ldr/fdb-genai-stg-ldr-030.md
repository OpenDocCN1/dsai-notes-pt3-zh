# 生成式AI战略领导者：P30：使用大型语言模型相互评分 📝

在本节课中，我们将要学习如何利用大型语言模型来评估其自身或其他模型的输出。随着模型快速迭代，我们精心设计的提示词可能面临失效的风险。本节将介绍一种自动化评估方法，以减少对人力的依赖，并确保提示词库的长期有效性。

---

上一节我们讨论了提示词维护的挑战，本节中我们来看看如何利用模型自身进行自动化评估。

大型语言模型本身正以极快的速度演进。我们已经见证了ChatGPT、GPT-4、LLaMA、Alpaca、Vicuna等模型的持续涌现。当我们投入大量精力开发出高效的提示词和模式后，一个关键问题是：如何评估并确保这些提示词能随时间推移保持有效？如果我们更换了底层大语言模型，是否所有提示词都会失效？或者，如果我们处理的数据略有变化，是否会产生连锁影响？因此，我们需要更好的方法来评估输出结果。

当然，一种方式是在许多情况下由人工审查输出。但我们更希望找到能够更好扩展的方法，即能够进行某种大规模自动化分析。

那么，我们该如何实现呢？大型语言模型一个非常有趣的特点是，我们可以利用它们来评估自身。这可以作为我们判断提示词质量及其长期可维护性的一个输入。我们可以使用一个大语言模型来给其自身或另一个大语言模型的输出打分。我们已经见过这样的例子：研究人员让一个大语言模型去“教导”另一个大语言模型。我们可以做类似的事情，将一个大语言模型的输出反馈给模型本身进行评分，或者使用另一个（可能参数更多、能力更强）的大语言模型来评估当前模型的输出。

让我们看一个具体的例子，了解如何构建一个提示词来实现这个目标。

在这个示例中，我将教导大语言模型（本例中是ChatGPT）如何给一个提示词的输出评分。在我的例子中，我实际上不会向它展示原始的提示词，而只是教导它评分过程，以便它能帮我实现自动化。我将使用一些“少量示例”的方法。

以下是构建评分提示词的步骤：

首先，我提供输入。输入是一段来自维基百科的关于范德堡大学的文本。它指出范德堡大学成立于1873年。

然后，我展示输出。输出是：“以下是事件和日期的列表：范德堡大学成立 1873”。

接着，我给出解释。解释是：输出开头包含了不需要的文本，应该只包含事件名称和日期。

最后，我进行评分。我给出了5分（满分10分）。

所以，我通过手动完成几个这样的示例，向模型展示我想要什么。

然后，我给出另一个示例，使用完全相同的输入文本。这次输出是：“1873”。这个示例的目的是（你现在可能已经感觉到了）我想要一个能提取事件及其发生日期的提示词，仅此而已。我想要“事件名称，日期”的格式，不想要任何其他文本或解释。我正在展示ChatGPT如何评估输出是否符合该格式。我甚至没有告诉它任务是什么，只是通过示例来帮助它学习。

对于这个输出，我的解释是：输出缺少关于该日期所发生事件的重要信息。我给出的评分是3分（满分10分）。

我还有第三个示例，输入同样是那段关于范德堡大学的段落。我展示的理想输出是：“范德堡大学，1873”。我解释：输出完全符合预期。然后我给出10分（满分10分）。有趣的是，即使我在解释中犯了点小错误（比如措辞不完美），这仍然有效。

完成这些“教学”示例后，我给出一个全新的输入。我说：这是一个不同的输入。这次是关于范德堡大学英语与创意写作项目历史的另一段文本。我给出输出：“亡命者与南方重农派，20世纪上半叶；范德堡大学是东南联盟创始成员，1966”。

这本质上就是一个提示词，让ChatGPT去评估那个输出。于是，它提供了一个解释。它甚至提到了我没有在评分标准中明确指出的问题（比如大小写不一致），这很有趣。然后它给出了9分（满分10分）。作为一个执行此任务的人类标注者，我最终也给了9分，因为它确实在大小写上不一致。但你可以看到，它做得很好。它理解了我想要的核心内容，并执行了我赋予它的评分任务。

因此，我们实际上可以使用大语言模型来评估提示词的输出。

---

现在，我们来看看这种方法的几种潜在应用场景。

以下是几种使用方式：

*   **自我检查**：如果你的系统使用像ChatGPT这样的大语言模型来做决策或生成信息，你可能希望让模型检查自身的输出。
*   **交叉验证**：或者，你可以用另一个模型来检查当前模型的输出。
*   **自动化流程**：你可能希望多次执行此操作。获取输出后，你提供一个类似我上面构建的评分标准，并开发一个包含该评分标准的提示词。你甚至可以拥有多个不同评分标准的提示词，让它们都对输出进行评分。如果分数低于某个阈值，你可以选择让人类查看该输出，或者只是重新尝试生成，看看是否能得到更好的结果。

这为你提供了一个额外的工具，用于评估输出结果，确保其质量，同时仍然利用这些模型的能力和复杂性。这是一种实现方式。

当然，构建提示词的方式有很多种。你可能想参考“替代方法”模式来开发一些不同的方式。我上面展示的是使用“少量示例”的一个例子。我也可以换一种方式，比如使用“角色扮演”模式：“扮演一个提示词批评家。我将为你提供输出。请根据其与提示词设计者期望的匹配程度进行评分。我将给你一些评分示例。” 我们可以那样做。我使用了一个相对简单的提示词，但我们也可以使用其他模式构建更复杂的提示词。它同样会生成解释，并在最后给出一个分数。

例如，当我们稍微修改提示词后，有时得到8分，有时得到9分。无论如何，根据我们的评分标准和期望，这看起来都是一个相当不错的输出。

因此，当我们需要评估一个提示词及其输出时，可以将此类工具纳入我们的工具箱。我们不必总是退回到依赖人工审查。我们可以转而让大语言模型自身评估输出，然后围绕此构建不同类型的自动化流程，或者将其作为触发条件，在必要时升级到人工处理。

当然，如果我们拥有大量高质量的评分示例，这对我们帮助很大。但正如你在我的例子中看到的，我们并不需要海量示例。仅仅三个评分示例，它就很好地理解了我的意图。
