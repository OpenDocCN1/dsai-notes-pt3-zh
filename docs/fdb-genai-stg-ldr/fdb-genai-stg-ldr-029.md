# 029：反应式提示 🧠

在本节课中，我们将学习如何构建能让大型语言模型（LLM）与外部工具和数据源交互的提示。我们将重点介绍一种名为“反应式提示”的方法，它通过示例教会模型在推理过程中识别何时需要借助外部工具，并学习如何使用这些工具。

---

大型语言模型虽然强大，但无法独立完成所有任务。它们需要能够访问其他数据源，并学会使用其他工具，才能随着时间的推移真正发挥效力。

因此，我们必须学会构建一种提示，使大型语言模型能够查询新信息，或使用其他工具来执行其本身不擅长的推理或计算任务。那么，我们该如何实现这一点呢？

## 反应式提示方法

实现这一目标的一种方法是采用“反应式”方法。其核心思想是，我们希望教会大型语言模型如何思考一个流程，理解在哪些步骤中它需要使用外部工具来执行某些操作，并将工具的结果带回，作为某种计算或结果融入其后续推理。

为此，有一种特定的提示编写方式。这与我们之前见过的“思维链”提示类似，我们将沿用其中的一些概念，但会扩展该方法，引入“模型知道需要使用外部工具”这一概念。

## 一个详细示例

让我们来看一个例子。请注意，这是一个较长的示例。我们将通过一个示例来教导语言模型，然后要求它执行类似的任务。

在这个任务中，我们需要计算：“为了让我的儿子准时参加Music City BMX全国赛的9-10岁公开赛，我需要在什么时间到达赛场？”BMX是一项自行车越野赛运动。Music City BMX是纳什维尔当地的一条BMX赛道，举办大型全国赛事。我需要弄清楚何时需要到达赛场，因为这是持续多日的全天活动。有时你想知道，在开车前往赛场前，最多能睡到多晚。比赛中，有数百个仅持续约30秒的小型比赛，称为“Moto”。你需要计算，例如，在第87个Moto开始前，需要等待多久。因此，有时需要权衡是“比赛何时开始”还是“我实际需要何时到达赛场”。

我们将让模型为我们解决这个问题。请注意，这是一个模拟解决问题的过程，并非实际解决，目的是展示其工作原理。

我们首先给出一个任务和一个示例：

**任务**：计算为了让我的儿子准时参加Music City BMX全国赛的9-10岁公开赛，我需要在什么时间到达。

**示例**（我们教导模型的思考过程）：
```
思考：我需要找出第一场比赛的开始时间。我可以使用网络搜索工具查询Music City BMX网站来获取该信息。
行动：搜索
查询：Music City BMX网站
结果：所有比赛在上午9点开始。
```

```
思考：我需要找出在9-10岁公开赛之前有多少个Moto。我可以使用网络搜索工具查询Music City BMX网站来获取该信息。
行动：搜索
查询：Music City BMX网站
结果：在9-10岁公开赛之前有30个Moto。
```

```
思考：我需要找出去年每个Moto的时长。我可以使用USABMX网站上的视频直播流，记录前10个Moto的时长。
行动：视频
查询：[假设的视频URL]
结果：前10个Moto耗时5分钟。
```

```
思考：如果10个Moto耗时5分钟，那么30个Moto将耗时15分钟。比赛在上午9点开始，所以我需要在8:50 AM之前到达。为了保险起见，我会提前30分钟，在8:45 AM到达。
```

记住，这是我们的“少样本”示例。我们模拟了一个场景：为了解决这个问题，我使用了一系列网络搜索，并观看了往年的视频来估算时长。我们正在教导大型语言模型（例如ChatGPT）使用相同的工具来解决问题。

## 应用所学：执行新任务

教导完成后，我们提出一个新任务：“计算我的36-40岁新手组比赛将在USA BMX Grand Nationals赛事中何时结束。”然后我们用“思考”来提示它开始推理。

以下是模型可能产生的反应（基于所学模式）：
```
思考：我需要找出USA BMX Grand Nationals第一场比赛的开始时间。我可以使用网络搜索工具查询USABMX网站来获取该信息。
行动：搜索
查询：USABMX赛事-grand-nationals
结果：（假设为本次练习）第一场比赛在上午8点开始。
```

```
思考：我需要找出在36-40岁新手组比赛之前有多少个Moto。我可以搜索...
行动：搜索
查询：USABMX赛事-grand-nationals
结果：（假设）有120个Moto在此之前。
```

```
思考：我需要找出去年每个Moto的时长。我可以使用视频直播流...
行动：视频
查询：[根据所学URL模式生成的假设URL]
结果：（假设）前10个Moto耗时6分钟。
```

```
思考：如果10个Moto耗时6分钟，那么每个Moto平均耗时0.6分钟。因此，120个Moto将耗时约72分钟。第一场比赛在上午8点开始，所以36-40岁新手组比赛将在上午9:12左右开始。我需要找出36-40岁新手组比赛本身会持续多久...
（模型继续推理，最终给出比赛结束的估算时间）
```

有趣的是，模型最终可能稍微偏离轨道（例如，它计算了开始和结束时间，而任务只要求结束时间）。但更重要的是，在整个过程中，它遵循了我们在示例中教导的模式。它学会了“搜索”和“视频”这些工具的概念，并在此处应用了完全相同的工具和格式。

## 实际系统集成与工具使用

在实际系统中集成此方法时，流程如下：

1.  **触发工具调用**：当模型生成一个“行动”（如`行动：搜索`）时，系统会暂停模型的生成。
2.  **执行真实工具**：系统将查询（如`查询：USABMX网站`）发送给真实的外部工具（如搜索引擎API）并获取结果。
3.  **注入结果并继续**：系统将获取到的真实结果作为“结果：”部分，与之前已生成的文本一起，作为新的提示输入回模型。
4.  **迭代循环**：模型基于新信息继续推理，直到生成下一个“行动”或最终答案。系统重复步骤2-3，直到模型输出最终结论。

更好的设计是让模型在最终输出时有一个明确的结束信号。但核心在于，通过示例，你教会了模型：“如果你需要某些信息，可以使用这些工具，并且请使用这种格式来描述你的工具调用。”

## 扩展：工具目录与描述

在上面的简单示例中，我们仅通过少样本示例直接提供了工具的使用模式。还有其他更强大的方法：

*   **工具目录**：你可以在提示中提供一个工具目录及其描述。例如：
    > 可用工具：
    > 1.  `search(query)`: 在互联网上搜索信息。输入应为搜索关键词字符串。
    > 2.  `calculator(expression)`: 执行数学计算。输入应为数学表达式字符串。
    > 3.  `get_weather(location, date)`: 获取特定地点和日期的天气预报。

然后，模型可以根据当前推理步骤的需要，参考这些描述来决定使用哪个工具以及如何格式化输入。这使它能够更灵活地进行问题解决，并与各种工具集成。

## 总结与框架应用

本节课中，我们一起学习了“反应式提示”方法。我们了解到，通过提供包含“思考-行动-结果”序列的示例，可以教导大型语言模型在解决复杂问题时，自主判断何时需要调用外部工具（如搜索引擎、计算器、数据库查询等），并学习如何以正确的格式调用这些工具。

这种方法使得LLM能够突破其固有知识和能力的限制，整合外部信息和功能，从而执行更复杂、更动态的任务。你现在看到的许多高级AI应用框架，例如**LangChain**，其底层就利用了类似“反应式”的机制来实现智能体的工具调用和自动化流程编排。

通过构建此类提示，你可以创建能够与外部世界交互、利用实时数据并执行特定计算的智能系统。
