# 生成式AI战略领导者：P36：请求输入模式 🎯

在本节课中，我们将学习一种名为“请求输入模式”的提示工程技巧。该模式的核心目标是控制大型语言模型的输出节奏，使其在接收完我们的指令后，暂停并主动向我们索要具体输入，而不是立即开始生成内容。

## 模式的核心思想

当我们与大型语言模型协作时，通常会在提示中描述一系列我们希望模型遵循的规则。这些规则将影响其输出，本质上是在“编程”这个模型。

上一节我们介绍了如何为模型设定规则。本节中我们来看看一个常见的挑战：如何防止模型在接收到规则后立即做出我们不希望的响应。

## 面临的挑战

有时，我们希望模型先理解规则，然后等待我们提供具体的输入，再将规则应用于此输入。例如，在一个“翻转互动”场景中，我们可能希望模型根据规则向我们提问，但我们只希望它一次问一个问题，而不是一次性生成10到20个问题。

因此，我们需要一种简单的方法，让大型语言模型能够倾听我们的指令，确认理解，然后等待我们提供输入。

## 解决方案：请求输入模式

我们可以通过“请求输入模式”来实现这个目标。其核心思想是让大型语言模型在听完规则后，主动向我们索要应用这些规则所需的输入。

以下是该模式的应用场景：
*   **翻转互动提问**：描述提问的规则后，只希望模型提出一个问题。
*   **生成替代方案**：描述生成替代方案的规则后，只希望模型先索要第一个任务，而不是自行虚构一个任务并开始生成。

## 一个反面案例

让我们看一个例子。在之前的视频中，我介绍了“替代方案模式”。当时它运行得非常有效，因为我实际上将其与“请求输入模式”结合使用了。

现在，我将展示不结合使用时的效果。我向模型输入了以下提示：
```
每当我要求你为我编写一个提示来完成某项任务时，请列出该任务是什么，列出创建该任务的替代方法，然后为每种方法编写一个提示。
```
我要求ChatGPT为“如何提示ChatGPT来解决任务”这件事生成多种替代方案。这回到了之前的概念：使用ChatGPT为自己生成提示，以辅助提示工程。

但我移除了一个关键部分。结果，ChatGPT回应说“当然”，然后它自行虚构了一个任务（“整理杂乱的书桌”），并为这个虚构的任务生成了三种替代方案。这并非我的本意，我的对话中因此充满了我不关心的额外内容。如果我试图创建一个具有一致性的交互体验，这将毫无帮助。

## 如何实施该模式

我们可以应用“请求输入模式”来解决这个问题。其做法非常简单：

在提示的**末尾**，告诉大型语言模型**请求下一个输入**。

具体操作如下：
1.  在提示中描述所有规则或要求。
2.  在最后加上一句指令，例如：“现在，向我询问第一个任务。”

这是一个示例提示结构：
```
[你的所有规则和指令描述...]
现在，请向我询问第一个任务。
```

这种方式相当于“切断”了大型语言模型，告诉它：“不要生成一大堆内容。我希望你停在这里，并询问我接下来想做什么。”这是一种将控制权交还给用户，让用户决定下一步操作的方法。

## 重要说明

与所有提示模式一样，当我们处理大型语言模型时，它具有一定程度的随机性。这意味着它并非每次都能完全一致地工作，此模式也可能无法保证100%成功。但实践证明，在提示末尾加上“请向我询问第一个输入”之类的指令，其可靠性非常高。

因为它向大型语言模型传递了一个明确的信号：它需要在此处暂停。

## 效果对比

如果我们对比使用该模式前后的输出，会发现结果更加聚焦。

*   **未使用模式**：模型可能生成一段冗长的、基于虚构任务的回应。
*   **使用模式后**：模型会回应：“当然，让我们开始吧。您希望我为哪个任务创建替代方案和提示？”

请注意，输入的核心部分是相同的，但末尾的指令“切断”了模型的自动延续，迫使它停下来等待我们的输入。
