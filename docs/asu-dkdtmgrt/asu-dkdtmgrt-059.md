# 黑暗数据迁移与架构：第21课：需求优先级排序与领导层协调 📊

在本节课中，我们将探讨评估工作的方向性产出，以及它如何影响我们从领导层获得的最初优先级排序。我们将讨论在专注于未知领域、进行迭代评估的阶段，如何向决策者提供反馈和调整建议，以推动价值交付。

上一节我们讨论了评估的框架，本节中我们来看看如何将评估结果转化为具体的行动优先级。

## 简单的优先级排序方法

![](img/b9bc464b0877a3d80b7892003e6916d3_1.png)

以下是公司常用的一些优先级排序示例。在深入更复杂的视图之前，我们先了解这些简单的方法。

左侧图表通常由用户价值和组织投入两个维度构成。公司、团队或个人可以绘制这样的图表，根据价值高低和投入大小来决定工作。这种方法不考虑时间、成本、影响或质量等因素，只给出“是”、“可能”、“否”的判断。

![](img/b9bc464b0877a3d80b7892003e6916d3_1.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_3.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_4.png)

可以看到，高投入高价值与低投入低价值项目会形成一种平衡。显然，低投入低价值的项目可以更快完成，因此你仍需要判断哪个是最佳选择。

右侧图表包含四个指标：**投入**、**价值**、**风险**和**成本**。两者都未涉及总体影响，但你可以通过这些指标来推算或管理影响。这个图表将项目分为四类：**避免**、**优先处理**、**考虑**和**调查**。

“调查”意味着我们需要进一步研究。“考虑”意味着我们需要纳入考量。“优先处理”则是我们将要优先执行的项目。

![](img/b9bc464b0877a3d80b7892003e6916d3_12.png)

就个人而言，我倾向于在头脑风暴阶段使用这类方法，尤其是在讨论其他更复杂的问题时，以初步了解各项事务的定位。这种方法的危险在于，它没有真正触及“影响”，而黑暗数据涉及的许多方面，你无法通过此方法获得清晰视图。

## 举措与关键性汇总

接下来我们继续看优先级排序的示例。顶部是**举措**，即战术上要完成的大型工作块。我们有：**营销活动现代化**、**数据质量平台提升**、**客户数据产品化**和**销售智能平台**。

![](img/b9bc464b0877a3d80b7892003e6916d3_34.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_35.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_36.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_28.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_29.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_30.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_31.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_32.png)

OKR1和2对应营销活动现代化；OKR3和数据质量平台提升对应客户数据产品化；OKR4和5对应销售智能平台。我们所做的是将关键性**汇总**。有些人喜欢用平均值，我个人喜欢汇总，因为它能体现价值的规模，而平均值则体现价值的平均水平。两种方法都相对正确，但需注意，使用平均值会产生许多小数点。通过汇总，我可以更直观地看到某项事务的关键性规模。

底部我们为那些OKR添加了名称，并写明了目标和关键成果：
*   **OKR1**: 确保在年底前通过数字渠道将客户群扩大20%。这个目标很高，但可以实现。
*   **OKR2**: 在年底前将国际客户群扩大10%。
    *   查看这两个OKR，一个针对渠道，一个针对市场（国际 vs 美国本土）。
*   **OKR3**: 在年底前将风险事件减少到少于4次。
*   **OKR4**: 在年底前将数据相关影响减少到少于5次。
    *   对于所有这些OKR，你仍然需要设定基线，尤其是这类“减少到少于…”的目标。例如，如果去年没有风险事件，你可能希望保持为零；但如果去年有50次风险事件，目标定为少于4次，那么关键问题是：我们具体要交付什么来确保实现？如果目标是“年底前”，但我们在8月才交付，在此之前可能已经发生了30次风险事件。因此，你必须考虑“未来”的数字，可能需要与领导层沟通，将其改为一个“未来目标”。例如：“基于X交付日期或X起始日期，将风险事件减少到少于4次。”可能需要设定某个日期之后的月度目标。
*   **OKR5**: 确保应用可用性达到四个九（99.99%）。
*   **OKR6**: 确保页面加载时间在两秒内。
    *   这关乎产品的性能表现。

## 处理依赖关系与调整优先级

现在我想指出一点。如果回到蓝色部分，查看销售智能平台与客户数据产品化的总权重，有人可能会说：“你需要先将数据产品化，然后才能放入平台。”我同意。此外，数据质量至关重要。

那么，我们是先提升质量，还是先建智能平台？或者说智能平台更重要？但如果我们使用平台时数据质量很差，或者数据没有恰当产品化，那么做那项工作就毫无意义。

我的建议是：通常，每个部分都可以在不同时间交付。尽管销售智能平台最关键，但现实情况是，你需要先完成**数据质量平台提升**和**客户数据产品化**，才能真正使用销售智能平台。

![](img/b9bc464b0877a3d80b7892003e6916d3_41.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_41.png)

因此，你可以做的是：**并行运行所有三项工作**，然后拆分销售智能平台的部分，先完成某些视图、数据段或业务线——无论哪个最重要。先理解并完成这些，从而实现端到端的交付。

![](img/b9bc464b0877a3d80b7892003e6916d3_43.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_44.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_43.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_44.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_45.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_45.png)

识别哪些部分最重要，这会促使你回过头重新审视那些OKR并说：“好吧，我们无法覆盖所有国际市场，可能只需要扩大EMEA（欧洲、中东、非洲）的消费者基础。”这样就不是全球范围，而只是一个区域。那么，前两个OKR就需要改为针对EMEA。

接着看OKR4和5，当它说“减少数据相关影响”时，如果基线已经很低，你可能可以降低质量平台提升的优先级；但如果基线很高，且需要大量工作才能减少到4或5次，那么你可能需要将其改为“在年底前将EMEA地区的风险减少到少于4次”，同时保留一个总体目标，但那个目标的关键性就不如专门针对EMEA的目标了。

因此，你需要根据实际需求来改变和调整这些OKR。这就是为什么关键性在其中扮演重要角色。

![](img/b9bc464b0877a3d80b7892003e6916d3_47.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_48.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_49.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_47.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_48.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_49.png)

思考一下，尽管我们理想上希望以某种方式做事，并且认为销售智能平台是关键，但这能防止业务人员只关注他们能看到的东西，因为销售智能平台将提供他们能理解和消化的可视化内容。而支撑它的底层技术也必须先行，因为那些部分需要先完成。

所以，当你考虑关键性优先级排序时，实际上，**数据质量和产品化更为关键**，因为它们是支撑你最终到达销售智能平台视图的“双腿”。

![](img/b9bc464b0877a3d80b7892003e6916d3_51.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_52.png)

![](img/b9bc464b0877a3d80b7892003e6916d3_51.png)
![](img/b9bc464b0877a3d80b7892003e6916d3_52.png)

但从业务角度看，由于他们使用销售智能平台，他们将其关键性定为16。但它依赖于另外两个。因此，你必须理清这些依赖关系，并确保将其向上汇报、调整那些OKR。调整OKR后，你可以将这些举措分解为史诗和功能，并在内部进行优先级排序。此时，关键性权重保持不变，但实际交付成果的工作量优先级则更符合工作执行的方式。你可以将其分解为MVP（最小可行产品），然后是MVP2，接着是版本2、3等，直到达到可供所有人使用的产品状态。

## 核心要点总结

这些是我们在讨论“评估理想状态可行性、缩小可能性范围”时需要关注的核心组成部分。在这里，我们看到了全部的可能性，现在正将其缩小到最理想和最可能的部分。

我们经历了这样的过程：现在我们看到了全貌，我们要做营销活动、数据质量、客户数据产品化和销售智能平台。现在我们要说：好吧，我们将EMEA、数据质量、产品化和销售智能平台作为最高优先级。然后从那里推进，确保按需交付，并随时间增长，扩大交付范围、扩展数据，同时那个平台也将注入我们在“可能性”阶段（即评估阶段）识别出的黑暗数据，从而改进洞察。我们还需要围绕质量、风险、期望和服务水平等设定一些指标。
