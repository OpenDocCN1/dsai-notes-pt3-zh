## 数据库设计流程

上一节我们介绍了数据设计的整体概念，本节中我们来看看数据库设计的具体流程。一个完整的设计流程始于发现与理解，并逐步细化。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_1.png)

以下是数据库设计的主要阶段：

1.  **发现**：遵循“理解、学习、评估和评估”的原则，这是所有设计工作的起点。
2.  **定义**：进入解决方案设计阶段。
3.  **概念设计**：确定系统的核心概念和实体关系。
4.  **架构设计**：规划系统的整体结构。
5.  **逻辑设计**：定义数据模型、表结构和关系。
6.  **物理设计**：当涉及硬件时，进行具体的物理存储设计。

设计阶段完成后，通常会进入构建、测试和交付等后续阶段。构建阶段本身也包含其自身的发现、设计和解决方案流程，因为在实际构建过程中，通常会对前期设计进行一些调整。如果前期设计工作做得充分，这些调整的幅度就不会太大。

此流程也包含最终的数据产品，但数据产品本身将在其他视频中详细讨论。在项目初始阶段，必须考虑暗数据以及从暗数据中衍生出的数据产品。

## 关键流程与工具

了解了设计流程后，我们需要掌握实现这些设计的关键工具和流程。它们是数据能被有效消费和创造价值的基础。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_7.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_8.png)

以下是支撑数据设计的关键组件：

*   **API**：应用程序接口，用于系统间数据交换。
*   **ETL**：提取、转换、加载过程，用于数据迁移和整合。
*   **数据可访问性**：确保数据能够被安全、高效地访问。
*   **数据可视化**：将数据转化为图表、仪表盘等直观形式，供消费使用。
*   **智能创建**：这体现在可视化内容中，使我们能够消费信息并做出更优决策。
*   **自动化**：自动化至关重要。当新数据流入（例如通过Kafka等事件监听方式流式进入）时，必须正确设置自动化流程，确保转换能及时完成，避免延迟。
*   **存储**：存储同样关键，因为它将容纳我们的信息和智能。

## 核心工具：ETL与数据转换

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_13.png)

在众多策略架构设计工具中，ETL是核心之一。ETL与数据转换高度相似，但也存在一些差异。

**ETL** 代表 **提取（Extract）、转换（Transform）、加载（Load）**。当数据在系统间迁移时，通常需要进行调整、转换或增强。ETL流程使我们能够接收数据，并以一种新的形式交付。

**数据转换** 则是一个更广义的概念。除了在ETL流程中发生，转换也可以发生在数据库内部，具体取决于整体代码的设置方式。例如，使用Python创建新的数据衍生字段就是一种数据转换。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_15.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_16.png)

```python
# 示例：使用Python进行简单数据转换
import pandas as pd
# 假设df是一个包含原始数据的数据框
df[‘新字段’] = df[‘旧字段’] * 2  # 创建一个衍生字段
```

## 数据存储架构：数据湖与数据仓库

接下来，我们深入探讨数据存储。我们之前提到过数据湖和数据仓库。

**数据湖** 通常存储更原始的数据。它经常包含大量不同类型和格式的数据。许多数据湖是部分结构化和部分非结构化的。实际上，大多数大型公司的数据湖都处于这种混合状态。你面对的是原始的、未定义的、海量的数据，需要对其进行治理、引入并理解。

数据科学家和机器学习工程师会利用各种用例来建立流处理过程，使用多种流程和技术从数据中学习，并开发新的流程和算法。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_18.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_19.png)

**数据仓库** 则通常存储更“干净”的数据。它通常是经过提炼的、小型的、关系型的数据集合。因为一旦数据表变得过大，其本身就会带来挑战，这也是为什么需要将数据转移到非结构化的湖中。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_20.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_21.png)

数据湖中也可能存在可用的、与数据仓库兼容的数据表，但并非总是如此。数据仓库的用户可以是分析师或任何需要数据的人，通常用于分析目的，而非事务处理。

理解数据湖或数据仓库是通过ETL流程或API接收数据，以及通过ETL和API提取数据的目的地，这一点非常重要。

## 数据存储架构详解：ODS、数据集市与数据存储

最后，我们来了解操作数据存储（ODS）。需要指出的是，在架构中还存在数据层、数据集市和数据存储等组件。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_26.png)

简而言之，数据从OLTP（联机事务处理）系统中流出，有时以平面文件的形式，进入临时区域，然后直接进入数据仓库。但有时，它们会先进入一个**数据存储**。

数据存储本质上是结构化的。根据本图的设置，这些数据存储通常将数据发送到数据仓库进行长期存储，而数据存储本身更具临时性，规模也较小，因此会发生大量的数据覆盖。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_28.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_29.png)

在最右侧，你会看到**数据集市**和其他可能需要输出的文件。请注意，在这些阶段之间都存在ETL流程，因为数据需要进行转换和加载。这些ETL流程通常基于算法或关系型数据库管理系统（RDBMS）中的参考数据运行。

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_31.png)

![](img/3f4c31cd7a0b8bc351cc2660fe21a5d3_32.png)

最终，最右侧的数据集市服务于用户，用于构建仪表盘或任何其他报告及智能分析目的。图中浅蓝色的**数据存储**是一个支持性机制，确保下游的一切得以发生。
