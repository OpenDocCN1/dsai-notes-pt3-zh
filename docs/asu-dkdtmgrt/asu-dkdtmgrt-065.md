# 黑暗数据迁移与架构：27：高层架构解析 🏗️

在本节课中，我们将学习一个分析系统的高层设计。我们将探讨如何构建一个能够提取和利用黑暗数据、支持数据分析产品，并具备可扩展性和前瞻性的系统架构。

## 概述

设计一个分析系统时，首要任务是关注**成果达成**。我们的设计能否如预期般支持价值实现？我们能否提取黑暗数据，并利用它创建数据产品来支撑分析系统？我们的设计能否对未来可能出现的故障保持警惕，并具备前瞻性，以便于扩展和扩充？此外，我们必须聚焦于**客户使用与参与度**。如果系统得不到采纳，就意味着它是无用的。我们需要确保所交付产品的每一个方面都能得到充分利用。

上一节我们介绍了设计分析系统的核心目标，本节中我们来看看一个具体的高层架构是什么样的。

一个典型的高层架构如下所示。我们拥有**运营系统**和**平面文件**。



![](img/16441d8eabac9b05df7874d021b4714a_3.png)

平面文件可以是JSON对象、电子表格、电子邮件，甚至是原始数据。这些文件进入系统后，会经过一些**处理**。处理过程可能包括数据存储，或者一个ETL（提取、转换、加载）流程，将数据从数据存储中提取出来，再加载到**数据仓库**中。

这里的数据仓库可以是数据湖（存储非结构化数据，使用NoSQL技术），也可以是传统的数据仓库（使用如MySQL、MSSQL等SQL技术）。在仓库中，我们存储**原始数据**和**元数据**，并有组件负责管理**数据模型**。此外，仓库中还包含**汇总数据**，即那些将向上游用户传递的汇总字段和值。



![](img/16441d8eabac9b05df7874d021b4714a_5.png)

![](img/16441d8eabac9b05df7874d021b4714a_5.png)

当我们思考元数据和原始数据时，还需要考虑**参考数据**。参考数据帮助我们生成汇总信息，或构建数据产品，亦或用于丰富来自其他多个来源的数据。所有这些数据都驻留在数据仓库中。



![](img/16441d8eabac9b05df7874d021b4714a_7.png)

![](img/16441d8eabac9b05df7874d021b4714a_7.png)

从数据仓库出发，我们向上游移动到**数据集市**。数据集市是针对特定主题或部门的数据集合，便于进行专项分析。

以下是常见的数据集市类型：

*   **销售数据集市**：分析销售业绩、区域表现等。
*   **市场营销数据集市**：分析营销活动效果、点击率、成本等。
*   **工程数据集市**：分析产品开发成本、周期、质量等。



![](img/16441d8eabac9b05df7874d021b4714a_9.png)

![](img/16441d8eabac9b05df7874d021b4714a_9.png)

以销售为例，如果有人问“哪些州的销售表现最好”，这里“表现”的含义就不同于“总销售额”。销售业绩是一回事，但**产品性能**则是另一个层面。谈论“表现更好”时，不仅指销售数字，还可能包括推荐率、产品退货率（例如，是否有用户利用系统规则反复购买并退货）等因素。如果涉及账户服务，还需要考虑用户是否在滥用系统。所有这些在评估“性能”时都需要纳入考量，而不仅仅是看“销售”数据。

在市场营销方面，考虑营销活动表现时，会涉及点击率、每次点击成本、关键词支出等数据。对于搜索引擎营销，活动表现取决于所有这些数据点，再加上申请数量（例如，点击后提交申请的比例）。但**表现评估**还包括用户账户的平均日余额、产品留存率或退货率等。因为市场营销和销售是并行且相互支持的。我们需要思考：是否在某些退货率较高的市场或用户群体中进行销售？这里的“退货”指的是产品退回，而非投资回报。



![](img/16441d8eabac9b05df7874d021b4714a_20.png)

![](img/16441d8eabac9b05df7874d021b4714a_21.png)

在架构的顶端，是**用户分析**和**常规分析**环节。这些部分允许你将数据可视化并内化，从而做出更优决策。

所有这些（销售、营销、工程中的深层考量）都是**黑暗数据**的不同组成部分。你需要在构建数据仓库的初期就将它们纳入其中，确保元数据、原始数据和汇总数据层已包含这些维度。然后，通过ETL等流程，这些数据沿着系统向上传递，支撑顶层的分析决策。

## 总结

![](img/16441d8eabac9b05df7874d021b4714a_28.png)

![](img/16441d8eabac9b05df7874d021b4714a_29.png)

![](img/16441d8eabac9b05df7874d021b4714a_30.png)

本节课中，我们一起学习了一个分析系统的高层架构。我们从成果达成和用户参与的核心目标出发，剖析了一个从数据源（运营系统、平面文件）到数据处理层（ETL、数据仓库），再到主题数据集市（销售、营销、工程），最后到达分析应用层的完整流程。关键在于理解，**黑暗数据**（如退货率、用户行为模式、工程成本细节）必须被整合进数据仓库的底层设计中，这样才能在后续的分析中释放其价值，帮助我们构建更强大、更具洞察力的数据产品，并确保系统能够适应未来的需求和挑战。
