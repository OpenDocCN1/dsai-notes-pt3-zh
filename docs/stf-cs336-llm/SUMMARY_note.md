# 斯坦福 CS336 课程笔记：从零构建大语言模型 📚

在本课程中，我们将跟随斯坦福 CS336 课程，系统地学习如何从零开始构建一个类似 ChatGPT 的大语言模型。课程内容涵盖从基础概念到高级技术的完整知识体系，包括模型架构、训练优化、推理部署以及对齐与评估等核心主题。

## 课程 1：大语言模型基础与分词技术 🔤

在本节课中，我们将要学习大语言模型的基本概念和文本处理的第一步——分词技术。

上一节我们介绍了课程的整体目标，本节中我们来看看大语言模型的基础与分词技术。大语言模型是一种基于海量文本数据进行训练的深度学习模型，能够理解和生成人类语言。分词是将原始文本拆分成模型能够处理的基本单元（即词元）的过程。

以下是分词技术的核心步骤：

1.  **文本规范化**：将文本转换为统一格式，例如统一大小写、去除多余空格。
2.  **子词切分**：使用算法（如 Byte Pair Encoding, BPE）将单词拆分为更小的、可重用的子词单元。这有助于处理未登录词和减少词表大小。
3.  **词元到ID的映射**：将切分好的子词词元映射到词表中对应的整数ID，形成模型可处理的数字序列。

一个简单的 BPE 合并操作可以用伪代码表示其核心思想：
```
while 合并次数 < 目标词元数:
    找到语料库中出现频率最高的相邻词元对 (A, B)
    将所有的 (A, B) 对合并为一个新词元 AB
    更新词表
```

## 课程 2：PyTorch 高阶技巧与训练资源核算 ⚙️

上一节我们学习了分词，本节中我们来看看构建模型所需的工具和资源规划。高效地实现和训练大模型需要熟练掌握深度学习框架并精确核算计算资源。

以下是本讲的核心内容：

1.  **PyTorch 高级特性**：包括自定义自动求导函数、使用 `torch.nn.Module` 和 `torch.nn.Parameter` 管理模型状态、以及利用 `torch.jit` 进行脚本优化。
2.  **训练资源核算**：估算模型训练所需的内存、计算量（FLOPs）和时间。这对于在有限硬件条件下规划实验至关重要。
3.  **性能剖析**：使用 PyTorch Profiler 等工具分析代码瓶颈，定位消耗内存和计算最多的操作。

关键的内存占用估算公式为：
**模型参数内存 ≈ 参数量 × 参数数据类型所占字节数**
**激活值内存 ≈ 批量大小 × 序列长度 × 模型隐藏层维度 × 中间层数 × 激活值数据类型所占字节数**

## 课程 3：大模型架构设计与超参数调优 🏗️

掌握了工具和资源核算后，本节我们将深入大语言模型的核心——Transformer 架构的设计与关键超参数的选择。

Transformer 架构由编码器和解码器堆叠而成，但其在大语言模型中通常仅使用解码器部分（即 GPT 系列模型）。核心组件包括自注意力机制和前馈神经网络。

以下是架构设计与调优的关键点：

1.  **模型尺度**：决定模型的参数量，通常通过调整层数、隐藏层维度和注意力头数来实现。
2.  **注意力机制**：理解多头自注意力如何工作，并关注其计算复杂度为 **O(n²d)**，其中 n 是序列长度，d 是隐藏层维度。
3.  **位置编码**：由于 Transformer 本身不具备序列顺序信息，需要注入绝对或相对位置编码。
4.  **超参数选择**：包括学习率、优化器（如 AdamW）、批量大小、预热步数和权重衰减等。这些参数对训练稳定性和最终性能有极大影响。

一个 Transformer 块的简化代码结构如下：
```python
class TransformerBlock(nn.Module):
    def __init__(self, hidden_size, num_heads):
        super().__init__()
        self.attention = MultiHeadAttention(hidden_size, num_heads)
        self.mlp = FeedForwardNetwork(hidden_size)
        self.norm1 = nn.LayerNorm(hidden_size)
        self.norm2 = nn.LayerNorm(hidden_size)

    def forward(self, x):
        # 残差连接与层归一化
        x = x + self.attention(self.norm1(x))
        x = x + self.mlp(self.norm2(x))
        return x
```

## 课程 4：混合专家架构实战 🧠

当模型规模变得极其庞大时，传统的稠密模型会面临巨大的计算开销。本节介绍一种高效的扩展方案——混合专家模型。

混合专家模型的核心思想是：对于每个输入，模型只激活一小部分“专家”网络进行计算，而非整个模型。这能在参数量大幅增加的同时，控制实际计算量。

以下是 MoE 架构的关键组成部分：

1.  **门控网络**：一个轻量级网络，根据输入决定激活哪些专家。例如，输出一个稀疏的权重向量。
2.  **专家网络**：多个独立的前馈神经网络，每个都是一个“专家”。
3.  **负载均衡**：引入辅助损失，确保所有专家都能被相对均衡地使用，防止某些专家过载而其他专家闲置。

MoE 层的前向传播可以表示为：
**输出 = Σ (门控权重_i * 专家_i(输入))**
其中，门控权重通常是稀疏的，只有 top-k 个值非零。

## 课程 5：GPU 原理与分布式训练基础 🖥️

训练大模型离不开强大的硬件支持。本节我们将了解现代 GPU 的架构原理，并初步接触分布式训练的概念。

GPU 拥有数千个核心，擅长并行处理大量相同的计算任务（单指令多数据流，SIMD），非常适合深度学习中的矩阵运算。

以下是 GPU 与分布式训练基础要点：

1.  **GPU 内存层次**：包括全局内存、共享内存和寄存器。高效编程需要优化数据在这些层次间的移动。
2.  **计算能力**：理解 FP32、FP16、BF16 等浮点数格式及其在训练中的权衡（精度 vs. 速度 vs. 内存）。
3.  **分布式训练动机**：当模型或数据过大，无法放入单卡时，需要将计算和存储分布到多个设备上。
4.  **通信原语**：介绍 `all-reduce`、`all-gather`、`broadcast` 等集体通信操作，它们是分布式训练的基石。

## 课程 6：内核优化与 Triton 框架应用 ⚡

为了极致压榨硬件性能，我们需要编写高度优化的计算内核。本节介绍内核优化思想和专用编程语言 Triton。

手动编写 CUDA 内核复杂且容易出错。Triton 是一种类似 Python 的开源编程语言，它允许开发者以更高的抽象级别编写高效的 GPU 内核，而无需深厚的 CUDA 知识。

以下是内核优化与 Triton 的核心：

1.  **优化目标**：最大化内存带宽利用率和计算吞吐量，减少空闲等待。
2.  **Triton 编程模型**：基于“块”的概念，自动处理线程网格和内存访问的优化。
3.  **应用场景**：用于实现自定义的、性能关键的算子，如融合的注意力计算或激活函数。

一个简单的 Triton 向量加法内核示例：
```python
import triton
import triton.language as tl

@triton.jit
def add_kernel(x_ptr, y_ptr, output_ptr, n_elements):
    pid = tl.program_id(axis=0)
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_elements
    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)
    output = x + y
    tl.store(output_ptr + offsets, output, mask=mask)
```

## 课程 7：分布式训练技术（上）：数据与流水线并行 🔄

从本节开始，我们深入探讨具体的分布式训练范式。首先介绍两种相对直观的并行方式：数据并行和流水线并行。

当单卡无法容纳整个批量数据时，可以采用数据并行。当模型层数过多，单卡无法容纳整个模型时，可以采用流水线并行。

以下是这两种并行方式的详解：

1.  **数据并行**：
    *   **原理**：将训练数据批次分割到多个 GPU 上，每个 GPU 持有完整的模型副本，独立计算梯度，然后同步聚合梯度并更新模型。
    *   **通信**：每个训练步骤后需要进行 `all-reduce` 操作来同步梯度。
2.  **流水线并行**：
    *   **原理**：将模型的不同层划分到不同的 GPU 上。像一个工厂流水线，微批次数据依次通过各个设备。
    *   **挑战**：存在“流水线气泡”，即部分设备在等待数据时处于空闲状态。通过精心调度微批次的顺序（如 GPipe 或 PipeDream 调度策略）可以缓解此问题。

## 课程 8：分布式训练技术（下）：模型与张量并行 🧩

上一节介绍了数据和流水线并行，本节我们来看更细粒度的模型并行技术：张量并行，它用于解决单个层（如庞大的前馈层或注意力头）无法放入单卡内存的问题。

张量并行将单个层内部的矩阵运算进行拆分，分布到多个设备上计算。

以下是张量并行的两种主要策略：

1.  **行并行**：将权重矩阵按行切分。每个设备持有部分行，处理完整的输入向量，产生部分输出结果，最后需要通过 `all-gather` 通信拼接完整输出。
2.  **列并行**：将权重矩阵按列切分。每个设备持有部分列，处理完整的输入向量，产生的结果已经是最终输出的一部分，通常需要 `reduce-scatter` 通信来汇总结果。

例如，一个线性层 **Y = XW** 的列并行拆分：
*   将权重矩阵 **W** 按列切分为 **[W1, W2]**，分布到两个设备。
*   设备1计算 **Y1 = XW1**，设备2计算 **Y2 = XW2**。
*   最终输出 **Y = [Y1, Y2]**，天然就是拼接好的（在某些激活函数下可能需要后续通信）。

在实际的大模型（如 Megatron-LM）中，通常结合使用这些并行策略。

## 课程 9 & 11：缩放定律 📈

在投入大量资源训练大模型之前，我们希望能预测其性能。缩放定律揭示了模型规模（参数、数据、计算量）与最终性能之间的经验关系。

缩放定律的核心结论是，在合理范围内，模型性能随着模型参数量、训练数据量和计算量的幂律关系而平滑提升。

以下是缩放定律的关键洞察：

1.  **计算最优边界**：对于给定的计算预算（FLOPs），存在一个参数量和数据量的最优分配比例，使得模型性能最好。通常建议同步增加两者。
2.  **损失预测**：测试损失 **L** 可以预测为关于可训练参数数量 **N**、训练数据量 **D** 和计算量 **C** 的幂律函数，例如 **L ≈ (C_min / C)^α**，其中 α 是一个常数。
3.  **指导意义**：缩放定律可以帮助研究者和工程师在扩大模型时做出更明智的决策，预估为达到特定性能目标所需的资源。

## 课程 10：推理 🚀

模型训练完成后，下一步就是部署并提供推理服务。本节讨论大语言模型推理阶段特有的挑战和优化技术。

推理与训练的关注点不同，它强调低延迟、高吞吐量和成本效益。

以下是推理优化的主要技术：

1.  **解码策略**：
    *   **贪婪解码**：每一步都选择概率最高的词元。简单快速，但可能错过全局最优序列。
    *   **束搜索**：保留 top-k 个候选序列，能提升生成质量，但更耗时。
    *   **采样**：包括随机采样、核采样等，增加生成的多样性。
2.  **推理优化**：
    *   **键值缓存**：在自回归生成过程中，缓存先前时间步的键值对，避免重复计算，大幅加速。
    *   **量化**：将模型权重和激活从高精度（如 FP16）转换为低精度（如 INT8/INT4），减少内存占用和加速计算。
    *   **模型编译与图优化**：使用工具（如 PyTorch TorchScript, ONNX Runtime）将模型转换为静态计算图并进行算子融合等优化。

## 课程 12：评估 📊

如何判断一个大语言模型的好坏？本节系统介绍评估大模型各类能力的标准、基准和注意事项。

评估是衡量模型进步、指导研究方向和应用落地的关键环节。

以下是模型评估的多维度视角：

1.  **能力评估基准**：
    *   **通用知识**：MMLU, C-Eval 等大规模多任务语言理解基准。
    *   **推理能力**：GSM8K（数学）, Big-Bench Hard 等。
    *   **代码生成**：HumanEval, MBPP。
2.  **评估方法**：
    *   **基于规则的评估**：对于有明确答案的任务（如数学），检查输出是否正确。
    *   **基于模型的评估**：使用另一个（通常更强的）模型来评判生成内容的质量，如 GPT-4 作为裁判。
    *   **人类评估**：黄金标准，但成本高昂且可能不一致。通常用于校准自动评估指标。
3.  **评估挑战**：避免数据泄露、确保评估集的多样性和难度、以及理解模型在特定任务上的泛化能力。

## 课程 13 & 14：数据（上 & 下） 🗃️

数据是训练大模型的基石。这两节课深入探讨大语言模型训练数据的全生命周期管理：从获取、清洗、去重到混合策略。

“垃圾进，垃圾出”的原则在大模型训练中尤为突出。高质量、多样化的数据至关重要。

以下是数据处理的核心步骤：

1.  **数据来源**：包括网页数据（Common Crawl）、书籍、学术论文、代码仓库（GitHub）和对话数据等。
2.  **数据清洗流水线**：
    *   **质量过滤**：基于规则（如语言检测、符号比率）或分类器模型去除低质量文本。
    *   **去重**：去除文档级、段落级甚至句子级的重复内容，防止模型记忆和过拟合。
    *   **安全与隐私**：移除包含个人身份信息或有害内容的文本。
3.  **数据混合策略**：确定不同来源数据（如网页、代码、对话）在训练数据中的混合比例。这显著影响模型在不同领域的能力平衡。

一个典型的数据混合比例可能遵循如下公式，为不同数据源 **i** 分配采样权重 **p_i**：
**p_i ∝ (数据源 i 的体积)^α**
其中 α 是一个介于 0 和 1 之间的指数，用于平滑体积差异带来的过度偏向。

## 课程 15, 16 & 17：对齐（监督微调、人类反馈强化学习 RLHF） 🤝

让一个拥有强大能力的基础模型安全、有用、诚实地遵循人类意图，这个过程称为对齐。这三节课详细讲解了当前最主流的对齐方法：基于人类反馈的强化学习。

基础模型通过无监督学习获得了广泛的知识，但未必能很好地遵循指令或符合人类价值观。对齐旨在解决这个问题。

以下是 RLHF 的三个核心阶段：

1.  **监督微调**：使用高质量的指令-回答对数据，对基础模型进行有监督训练，使其初步学会遵循指令。
2.  **奖励模型训练**：
    *   收集人类对模型多个回答的偏好排序数据。
    *   训练一个奖励模型，其目标是使得人类偏好的回答获得比被拒绝回答更高的奖励分数。
3.  **强化学习优化**：
    *   将 SFT 模型作为需要优化的策略。
    *   使用训练好的奖励模型作为奖励信号。
    *   通过近端策略优化等 RL 算法，最大化策略生成回答所获得的期望奖励，同时通过 KL 散度惩罚防止策略偏离原始 SFT 模型太远。

RLHF 的目标可以形式化为以下优化问题：
**最大化 E_(x∼D, y∼π_θ(·|x)) [R_φ(x, y)] - β * KL(π_θ(y|x) || π_ref(y|x))**
其中，**π_θ** 是待优化的策略模型，**π_ref** 是参考模型（通常为 SFT 模型），**R_φ** 是奖励模型，**β** 是控制偏离程度的系数。
