## 线性时态逻辑简介 ⏳

![](img/39a6326e9c10dd020cb75d1ced02dc8e_21.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_23.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_25.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_26.png)

在之前的课程中，我们主要使用命题逻辑来描述单个状态下的条件。然而，许多现实世界的问题，如交通规则，需要在**一系列状态**中持续满足某些条件。线性时态逻辑提供了一种强大的形式化方法来描述系统随时间变化的属性。

上一节我们介绍了时态逻辑的基本概念，本节中我们来看看线性时态逻辑的具体定义。

线性时态逻辑基于**线性时间模型**，这意味着我们考虑系统沿着一条单一的、无限延伸的时间线（状态序列）演化。这与分支时间模型不同，后者会考虑所有可能的未来路径。对于规划任务，线性时间模型更为实用，因为它允许我们对给定路径进行精确分析。

![](img/39a6326e9c10dd020cb75d1ced02dc8e_28.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_30.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_32.png)

LTL公式作用于一个无限的状态序列。在每个状态，可以有各种命题为真或假。除了标准的逻辑运算符（如与、或、非），LTL还引入了关键的**时态运算符**，用于描述跨时间的属性。

![](img/39a6326e9c10dd020cb75d1ced02dc8e_34.png)

以下是核心的时态运算符及其含义：

![](img/39a6326e9c10dd020cb75d1ced02dc8e_36.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_38.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_40.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_42.png)

![](img/39a6326e9c10dd020cb75d1ced02dc8e_43.png)

*   **X (Next)**: 公式 `X P` 在某个状态为真，当且仅当在**下一个状态**，`P` 为真。
*   **F (Future / Eventually)**: 公式 `F P` 在某个状态为真，当且仅当在**未来的某个状态**（不一定是下一个），`P` 为真。
*   **G (Global / Always)**: 公式 `G P` 在某个状态为真，当且仅当从当前状态开始，**所有未来状态**中 `P` 都为真。
*   **U (Until)**: 公式 `P U Q` 在某个状态为真，当且仅当存在一个未来状态使得 `Q` 为真，并且**直到**那个状态之前，`P` 一直为真。
*   **R (Release)**: 公式 `P R Q` 是 `U` 的对偶运算符。它要求 `Q` 必须一直为真，**直到**某个状态使得 `P` 和 `Q` 同时为真；在此之后，`P` 不再被强制要求。

![](img/39a6326e9c10dd020cb75d1ced02dc8e_45.png)

这些运算符可以组合使用，以表达复杂的时态属性。例如，“最终永远为真”可以表示为 `F G P`，而“无限经常为真”可以表示为 `G F P`。

## LTL示例与应用 🚦

了解了LTL的语法后，我们来看看如何将其应用于具体的规划问题。

以自动驾驶汽车为例，我们可以用LTL公式形式化地描述交通规则：

1.  **在红灯前停车**：`G( red_light -> X(stop U green_light) )`
    *   含义：**总是**，如果看到红灯，则**下一个**状态开始**停车**，**直到**看到绿灯。
2.  **始终遵守限速**：`G( speed <= speed_limit )`
    *   含义：**总是**，速度小于等于限速。
3.  **最终需要加油**：`G F at_gas_station`
    *   含义：**总是**，**最终**会到达加油站（即无限经常需要加油）。

这些公式描述了需要在**整个路径**中满足的条件，而不仅仅是在最终目标状态。

为了将LTL目标应用于自动规划器，我们需要将其转化为规划器能理解的语言。一种常见的方法是使用 **PDDL3**，它是规划领域定义语言的一个扩展，支持部分LTL运算符。

以下是PDDL3中表达时态约束的一些关键构造：

*   `(at end <goal>)`: 在计划结束时满足目标（经典目标）。
*   `(always <condition>)`: **总是**满足条件。
*   `(sometime <condition>)`: **最终**在某个时间点满足条件。
*   `(within <n> (sometime <condition>))`: 在`n`步内**最终**满足条件（可用于模拟`next`）。

例如，`(sometime (traffic_light green))` 对应LTL中的 `F green`。

另一种更强大的方法是将LTL公式转化为 **Büchi自动机**。Büchi自动机是一种能够接受无限状态序列的有限状态机。通过将LTL规约问题转化为在组合系统（原始状态空间 × Büchi自动机）中寻找一条被自动机**接受**的路径，我们就可以利用现有的模型检验或规划算法来求解。

从Büchi自动机可以进一步转换回标准的PDDL描述，从而利用经典规划器进行求解。这个过程涉及到将自动机状态编码为新的命题或派生谓词，并将接受状态设置为规划的目标条件。

## 整合偏好进行规划 ⚖️

在实际规划中，除了必须满足的**硬性目标**（用LTL描述），通常还有我们希望满足但非强制性的**偏好**。偏好允许我们在多个能达成目标的可行计划中，选择更优的一个。

偏好规划问题在经典规划问题`<S, A, I, G>`的基础上，增加了一个**偏好关系R**，用于比较计划之间的优劣。

偏好语言主要分为两类：
1.  **定量语言**：为每个计划分配一个数值（成本或效用），通过比较数值大小来决定偏好。例如，最小化违反某条交通规则的次数。
2.  **定性语言**：直接声明一种计划属性优于另一种，而不指定具体程度。

PDDL3也支持表达偏好。可以使用`preference`关键字来标记一个希望满足的条件，并在优化指标中使用`is-violated`函数来最小化违反该偏好的次数。

例如：
```lisp
(:metric minimize (is-violated stop_at_red))
```
这表示规划器会尝试最小化“在红灯前停车”这条偏好被违反的次数。

一个更高级的偏好语言是 **LPP**。它采用分层、定量的方式来组合偏好：
1.  **基本期望公式**：即LTL公式，描述时态扩展的命题。
2.  **原子偏好公式**：为BDF分配权重，表示对其的期望程度（权重越低越优先）。
3.  **一般偏好公式**：使用逻辑运算符组合APF。例如，`OR`操作试图满足权重最低的选项，而`AND`操作试图最小化所有选项中最大的权重。
4.  **聚合偏好公式**：定义当无法满足所有偏好时，放松（忽略）偏好的优先顺序。

使用LPP等语言，规划器（如`PPlan`）可以在搜索过程中，同时考虑时态逻辑目标和偏好，最终找到一个在满足硬性约束的前提下，尽可能符合我们偏好的最优计划。

## 总结 📚

本节课我们一起学习了时态逻辑规划的核心内容。

我们首先介绍了**线性时态逻辑**，它通过`X`（下一个）、`F`（最终）、`G`（总是）、`U`（直到）等运算符，能够描述在时间序列上必须满足的属性，这对于定义如交通规则之类的持续性子目标至关重要。

接着，我们探讨了如何将LTL应用于**规划问题**，包括通过PDDL3直接描述，以及通过转换为Büchi自动机再利用经典规划器求解的技术路径。

最后，我们学习了如何将**偏好**整合到规划过程中。偏好允许我们在多个可行解中做出更符合期望的选择，可以通过PDDL3的简单度量实现，也可以通过如LPP这样更表达力丰富的分层语言来描述复杂的偏好关系。

![](img/39a6326e9c10dd020cb75d1ced02dc8e_47.png)

通过结合时态逻辑目标和偏好，我们能够为机器人等自主系统制定出不仅正确，而且更高效、更安全或更符合人类期望的行为计划。
