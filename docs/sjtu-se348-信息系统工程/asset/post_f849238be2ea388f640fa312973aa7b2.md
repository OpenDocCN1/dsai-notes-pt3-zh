# 分布式数据规划步骤
分布式数据规划加细

- 规划矩阵可以表示数据结构而不是主题数据库，矩阵的主要部分可以指出已经存在的数据结构
- 一个数据结构既可以是一个文件，也可以是一个数据库，两者都可以是联机的或脱机的。数据结构有的很简单，最简单的可以是一个字段；有的相当复杂，如有12个物理数据库，多个不相交的数据库存在于一个数据库系统之中，形成一个数据结构。
- 选择数据结构或数据结构定位，有下列可能的约束：
  - 所考虑的机器上没有数据库管理系统
  - 所采用的数据库管理系统对所允许的数据结构有限制
  - 数据结构已经适应现有的应用项目，而转换代价太高
  - 外围计算机或小型/微型计算机存储能力有限
  - 外围计算机缓冲区大小/数目有限
  - 外围计算机的地点使安全性受限制
  - 必须规划数据的完整性控制
  - 机器发生故障期间必须提供恢复手段
  - 如果数据偶然丢失，必须能重新组织
  - 必须设计重新启动过程，以便数据更新不被丢失或重复处理

6. 画出地理数据结构矩阵，实际上是步骤5的扩充，这样矩阵可能变得很大，可以分成几页画。虽然用了“地理”这个词，一些分散的数据结构也可能离得相当近，很可能就在同一座大楼内

7. 要进行一些关于数据定位的实际限制检查，包括故障恢复、安全性和、重启动，以及可能引起以地理数据结构矩阵为前提的调整，这种调整将回到步骤6 修改数据结构矩阵

8. 决定要用哪些事务处理，要有哪些应用程序来完成这些处理，然后形成一张矩阵表，指出每个程序使用哪些数据结构。
有时该表类似于地理数据结构矩阵，有时差别很大，因为一个业务过程要用几个事务处理和多个应用程序，而且有些程序可以驻留在它们所服务的不同的地理结点上。在具有完全集中式的远程处理系统中，大多数应用程序与最终用户的终端所在地都有地理上的距离
