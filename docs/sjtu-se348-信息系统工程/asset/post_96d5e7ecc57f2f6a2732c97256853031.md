## 小结：不含有复合数据项的数据结构
是一范式（1-NF）的结构

非一范式的数据结构：

| 工号 | 姓名 | 基本工资 | 奖金项目-金额 | 扣款项目-金额 | 实发金额 |

一范式的数据结构：

| * 工号 | 姓名 |

| * 收入代码 | 收入名称 |

| * 扣除代码 | 扣除名称 |

| * 工号 | * 收入代码 | 收入金额 |

| * 工号 | * 扣除代码 | 扣除金额 |

基于规范化的“工资数据结构”，可开发出不需要维护的工资程序

## 概念数据库与概念数据库标准

- 概念数据库（Conceptual Database）是最终用户对数据存储的看法，是对用户信息需求综合概括，简单说，概念数据就是主题数据库的概要信息

- 概念数据库一般用数据库名称及其内容的描述来表达。例如：
  - 船舶动态 船舶资料、预到港、锚地、作业及待离港船舶动态信息
  - “船舶动态”是数据库的名称，后边列出的“船舶资料、预到港、锚地、作业及待离港船舶动态信息”则是对该数据库内容的描述

- 概念数据库标准是指列出全企业所有的主题数据库的概要信息

- 经过总体数据规划工作，根据企业性质和规模，有的列出30个左右，有的列出50个左右的主题数据库概要信息，这就是企业概念数据库标准

## 概念数据库标准的建立不是一件简单工作

- 随便列出一些“主题数据库”，是没有任何标准意义的

## 逻辑数据库（Logical Database）

- 逻辑数据库是系统分析设计人员的观点，是对概念数据库的进一步分解和细化，一个逻辑主题数据库由一组规范化的基本表（Base Table）构成。

- 基本表是按规范化理论与方法建立起来的数据结构，一般要达到“三范式”（3-NF）

- 企业的逻辑数据库标准是指以基本表为基本单元，列出企业全部的逻辑数据库
