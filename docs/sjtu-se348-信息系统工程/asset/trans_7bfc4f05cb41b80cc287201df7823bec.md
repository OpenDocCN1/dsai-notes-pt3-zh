

## 逻辑数据库标准例

- 港口生产管理信息系统的“船舶动态”（逻辑的）主题数据库标准如下：
- 船舶动态基本信息（* 船舶航次编号，船舶动态码，船名，呼号，来自港，...）
- 船舶动态-预报船（* 船舶航次编号，预计抵港时间，抵港时间，抵港吃水，...）
- 船舶动态-锚地船（* 船舶航次编号，下锚时间，锚位，预靠时间，...）
- 船舶动态-靠泊船（* 船舶航次编号，* 泊位号，* 靠泊时间，泊位船状态码，...）
- 船舶动态-作业船（* 船舶航次编号，* 泊位号，* 装卸标志，* 开始时间...）
- 船舶动态-开航船（* 船舶航次编号，实卸吨，实装吨...）

其中，第一个基本表与其后的基本表错开排列，是因为它有特殊的、综合的性质，它对其后的基本表都有“一对多”的关系。每个基本表后边括号内的属性列表项，都是数据元素，其中前面加* 的是主键关键字

## 逻辑数据库标准的建立不是一件简单工作

- 这里仅列举了港口生产管理信息系统的几十个概念主题数据库中的一个逻辑数据库标准，要把所有概念主题数据库都规范化到逻辑主题数据库，并且得到行业内有关人员的共识，是一项极其艰巨的工作
- 这项工作一般不是一次性的，不是短时间可以完成的，也不是少数人可以完成的。要完成这项工作，决定性的因素是需要组建一个训练有素的工作班子，需要正确的理论与技术指导，还需要计算机辅助工具的支持
- 由于缺乏标准和一致性，信息系统开发工作的初期阶段是杂乱无章的。每个分析员设计系统所使用的方法都与其他分析员的方法不同。程序员们倾向于用独有的方法来为每个程序编码，他们几乎没有什么训练和一致性原则，致使研制出的系统差不多都是支离破碎、繁琐复杂的，维护费用十分昂贵

## 数据字典的基本内容

- 数据字典提供了关于数据元素、元素组（记录或片段）、记录组（文件或数据库表）信息的定义和使用机制，以及这些数据实体之间的联系
- 数据字典还可以定义其他一些对象，例如，输入格式、报表、屏幕界面、处理程序模块等
- 但是，所有数据实体定义是建立在数据元素定义的基础之上的

元素名：US-POSTAL-STATE-CODE
创建者：应付账款管理部门
编号：02 JUL 81 AT 15; 13
别名/同义词：
  COBOL：US-POSTAL-STATE-CODE
  IMS：STCODE

  POSTAL ST CD

有效值：
  AK = Alaska
  AL = Alabama
  AZ = Arizona
  AR = Arkansas
  CA = California
  CO = Colorado
  CT = Connecticut
  DE = Delaware
  DC = District of Columbia
  FL = Florida
  GA = Georgia
  HI = Hawaii
  ...
  VI = Virgin Islands
格式：2 位大写字母

## 数据字典中
一个数据元素定义的实例

这一数据元素定义回答了有关一个特定数据的下述问题：

- ✓ 该数据的名称是什么？（元素名）
- ✓ 谁完成的定义？（创建者）
- ✓ 何时完成的定义？（编号）
- ✓ 在COBOL程序中该数据的名称是什么？（COBOL别名）
- ✓ 在IMS中该数据的名称是什么？（IMS别名）
- ✓ 数据字典对该数据元素如何实现自动检索？（分类）
- ✓ 该数据的意义是什么？（说明）
- ✓ 该数据与其他数据的关系是什么？（注意）
- ✓ 该数据的有效值有哪些？（有效值）
- ✓ 该数据存储的格式和长度是什么？（格式）

## 数据字典中
不同阶段，同一个数据元素定义详细程度不同

- 在总体规划阶段
  只需要界定数据元素的标识和名称（如“数据元素标准”），称做概念数据字典

- 在系统设计阶段
  要界定数据元素的数据类型、长度等，称逻辑数据字典

- 在系统建造实现阶段
  要说明数据元素在具体应用系统内是什么样的，以及如何被使用的（如表2-2中所列），称做物理数据字典

- 基于数据元素的记录、库表等数据实体的元数据，以及与数据实体关联的程序模块等元数据，也将分别存储在概念数据字典、逻辑数据字典和物理数据字典之中

## 数据管理与数据字典、数据库的关系

- 当问到什么是数据管理时，程序员或分析员会有两种典型的、模糊的回答：
- 数据管理与数据字典有些关系
- 数据管理与数据库有些关系

- 这样的回答并不是完全正确的，他们只是说到了数据管理所使用的工具或设施，他们并没有恰当地解释出数据管理的目的

- 数据库和数据字典，是数据管理人员可以使用的资源和工具，但这仅仅是整个目标的一个方面

- 数据管理的整个目标是规划、管理控制全企业的信息资源。数据字典和数据库帮助达到这一目的，但是两者本身并不是最终目的

- 数据管理的任务并不是维护个别的数据库和数据字典。数据管理的任务是通过使用数据字典和设计良好的数据结构，来集中管理全企业范围的信息资源

## 问题一
已经有了数据字典，为什么还需要数据管理？

为了从数据字典获得最大的投资回报，数据管理人员必须向主管部门提供下述问题的答案：

- （1）建立数据字典要达到的目的是什么？建立数据字典的成本和效益是什么？
- （2）什么信息应该装到数据字典中去？
- （3）谁负责数据字典的信息输入工作？
- （4）这些信息输入字典前谁必须负责检查和批准？
- （5）输入前确保这些信息质量的步骤是什么？
- （6）一旦信息输入字典，将如何对它进行维护？
- （7）谁负责字典中数据一致性的维护？
- （8）该字典将如何用于新系统的开发或辅助现行系统的维护？
- （9）该字典将支持哪几种软件语言？

## 问题二
已经有数据库管理员，为什么还需数据管理员？

- 数据库管理员（Data-Base Administrator，简称 DBA）负责物理数据库（Physical Database）的设计、实现、安全性和维护工作
- 数据管理员（Data Administrator，简称 DA）的职责，在于确定每个数据库的内容和范围
- 数据管理首先建立数据库的逻辑模型（Logical model），随后由 DBA 来实现
- 这类似于系统分析员和系统设计员之间的区别。尽管在数据管理之前，DBA 就可以设计单个的逻辑的和物理的数据库，而数据管理则应该致力于规划和协调整个组织的所有数据库的建设

## 数据管理应该提供对下述问题的回答

- （1）今后几年计划开发多少新的数据库？
- （2）这些数据结构的实现能否保证业务系统规划的长期目标，或该企业的其他业务需求？
- （3）怎样建造这些数据库才能使数据库中信息冗余最少？
- （4）这些数据库之间需要哪些通讯？
- （5）这些数据库按什么顺序来实现？
- 数据管理员应该制定出整个组织对数据使用的业务系统规划
- 假如物理数据库系统已经建立起来而没有考虑整体规划，这些数据库将会引起相同数据的不相容性、不一致性，以及它们正在替换的数据结构的冗余性

## 数据管理员和数据库管理员的职责区别

| | 数据管理 (DA) | 数据库管理 (DBA) |
|---|---|---|
| 主要职责 | 管理上 | 技术上 |
| 范围 | 所有数据库 | 特定数据库 |
| 数据设计 | 逻辑的 | 物理的 |
| 主要联系人 | 管理人员 | 程序员，系统分析员 |
| 关注问题 | 长期数据规划 | 更关心短期数据库的开发和使用 |
| 主要倾向 | 元数据<br>数据字典<br>数据分析<br>DBMS 无关性 | 数据<br>数据库<br>数据设计<br>特定的 DBMS |
