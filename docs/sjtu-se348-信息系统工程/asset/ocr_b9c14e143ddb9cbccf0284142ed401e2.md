# 分布式数据规划步骤

6. 画出地理数据结构矩阵，实际上是步骤5的扩充，这样矩阵可能变得很大，可以分成几页画。虽然用了“地理”这个词，一些分散的数据结构也可能离得相当近，很可能就在同一座大楼内

7. 要进行一些关于数据定位的实际限制检查，包括故障恢复、安全性和、重启动，以及可能引起以地理数据结构矩阵为前提的调整，这种调整将回到步骤6 修改数据结构矩阵

8. 决定要用哪些事务处理，要有哪些应用程序来完成这些处理，然后形成一张矩阵表，指出每个程序使用哪些数据结构。
有时该表类似于地理数据结构矩阵，有时差别很大，因为一个业务过程要用几个事务处理和多个应用程序，而且有些程序可以驻留在它们所服务的不同的地理结点上。在具有完全集中式的远程处理系统中，大多数应用程序与最终用户的终端所在地都有地理上的距离
