## 应用开发组的基本职责

- 整个企业计算机化的任务十分庞大，需要明确开发与使用的职责，组织多个开发小组，分期分批地进行开发工作
- 有些项目应该由中心小组来开发，如总帐、预算、采购
- 有的项目由其它小组来开发，如三个工厂中的一些项目
- 有些项目要求对业务过程与活动有透彻的了解，必须与最终用户联合进行开发

### 数据分布定量分析的目标

- **分布的理由**
  - 随计算机硬件价格的下降（比网络资费的价格下降速度快得多！），把数据和程序都放到与用户活动相同的地方，似乎更有利
- **集中的理由**
  - 许多数据都是被多处的活动所共享的，如果把这些数据复制存储到每个用户地点的计算机中，对这些数据修改时，就必须对分布到每个地点的数据进行修改。如果数据被多处的活动更新，而且这些被更新后的数据必须是最新的，要得到这样数据的一个副本是容易的，但要保存多个最新最准确副本是复杂的，传送量大为增加，同时还要对可能发生的各类故障作复杂的恢复处理。对这种情况如果用一个副本，就可以达到降低数据集之间相互关联性
- **目标**
  - 定量方法试图以某种途径来安排数据和处理的地点，使得各地点之间的传送量和相互影响最小
  - 一个良好的分布式规划应该把数据与程序聚集成一些组，每一组都有高度的自主权，组与组之间具有较低的相互关联性

### 结点间的传送量计算

- 考虑一个具有N个终端的系统，这N个终端分布在N个不同的地点，用户在这些地点进行一些事务处理（有的使用数据，有的修改数据）
- 假定
  - **Au** 表示每小时发生的使用数据的操作数
  - **Ac** 表示每小时发生的修改数据的操作数
  - 上述操作均匀地分布在N个用户位置上
- 定义传送量单位为一个报文（message）——被传送到一个结点并由该结点发回响应信息
- 假定数据是集中在一个用户结点处，每小时系统总的传送量单位是：

  ![](img/66d4369fd16c75b43d6800360af39d15_893_0.png)

- 如果数据是非集中的（譬如，存放在所有用户地点），那么使用数据的操作就不发生传送，而修改数据的操作每次发生N-1个传送量单位，这样，每小时系统总的传送量单位是

  T非集中的 = A_c (N - 1)

- 如果：

  (A_u + A_c) (N - 1)/N > A_c (N - 1)

  A_u / A_c > N - 1

- 则数据分布存储比集中存储所产生的传送量少

### 需要考虑的其它复杂问题

- 用户设备的操作费用多少？是否有其它类型的事务处理需要查找整个数据集，或者从中提取汇总信息？
- 当多个相同的数据副本被维护时会有什么软件问题？
- 所有类型的故障都可能出现，故障发生后如何恢复？在恢复故障期间再发生故障怎么办？
- 需要什么样的网络结构？

传送量计算本身并不能回答这样的问题：是应该采用还是不采用分布式结构？然而，这种计算却能提供在配置计算机的多种方式之间什么样的数据应该采用分布式的见解
