# 两大类、四小类系统的区别

- □ 日常和非日常系统的区别

- ■ 日常处理系统执行一些预定的操作: 定货, 帐单, 保险申报等日常处理以及简单的查询。这类处理的活动量往往都很大

- ■ 非日常系统有各种类型

- ✓ 对数据库设计人员尤其重要的是综合信息系统，用户在综合信息系统中搜索信息，提出难以预见的查询，或者进行可以预见，但需要使用辅助关键字的查询操作

- ✓ 其它非日常系统包括优化计算系统和决策支持系统

- □ 上述子系统划分方法过程中没有考虑两大类四小类系统之间的区别，可以对它进行修改，以便考虑这一因素

# （1）日常处理系统

- 预定的任务、决策规则和事务流
- 处理量往往很大
- 大批量的传统数据处理
- 主要效益：事务处理效益提高，周转速度加快，提高简单查询的处理速度，减少库存，节省人员
- 设计时主要考虑因素：大批量作业的效率
- 通常从第三类数据库方法中获益

# （2）综合信息系统

- 回答非结构化的和难以预计的查询，或者启动辅助关键字
- 操作的查询
- 生成报表
- 主要效益：为决策者提供更好的信息
- 设计时主要考虑因素：功能强大的最终用户语言，友好的用户界面和管理操作的有效性
- 从第四类数据库方法中获益

# （4）优化计算系统

- 为某些类型问题提供解答，这类问题通常是良好结构化的
- 主要效益：为处理复杂问题提供新的方法
- 可以使用从数据库中导出的文件

# 繁忙处理过程的区分

- 下图列出繁忙的处理过程，它们进行大量例行的日常事务处理。通常，需要把这些系统的数据库与综合信息系统或决策支持系统的数据库分开。

- 繁忙系统的数据组织和存取方法，要经过仔细地协调，以适应它们对大量日常数据的使用。综合信息系统和决策支持系统中的数据组织往往具有更大的灵活性，存取工作量较小，存取方法更适于检索数据，或者为功能强大的最终用户语言服务。

# 日常／非日常事务处理子系统的标注

- 下图是在上述图的基础上表明了支持主要**日常事务处理的子系统**（黑色的方框）、独立的综合信息子系统和决策支持系统（圆）。图中线条表明日常事务子系统之间的数据流。其它子系统所需的信息从这些子系统中派生出来，这些派生出来的信息往往是一些汇总数据。综合信息系统和决策支持系统，并不对其它数据库中的数据进行更新。

- 这种将数据分成若干子系统的方法，并没有精确的算法，它需要人的判断力。只要任何一个子系统具有基本独立的职能或数据使用，那么它就应该被分开。只要有可能，就应该将大型复杂的系统分成若干子系统。这样，一个开发小组就能够比较容易地实施这个子系统。
