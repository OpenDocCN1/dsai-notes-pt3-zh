# AI提示词工程：P1：深入探究

## 概述

在本节课中，我们将深入探讨AI提示词工程的核心概念。我们将从多位专家的视角出发，解析什么是提示词工程、如何成为一名优秀的提示工程师，并探讨其未来发展趋势。课程内容将涵盖从基础定义到高级技巧的各个方面，旨在为初学者提供一个清晰、全面的入门指南。

## 什么是提示词工程？

提示词工程的核心是尝试让模型完成特定任务，充分发挥模型的潜力，实现原本无法实现的目标。这本质上是一种沟通行为，类似于与人交谈。然而，与人类沟通不同，与模型对话时，你拥有一个“重启按钮”，可以随时回到起点，重新开始尝试。这种能够独立实验和设计不同方案的能力，正是“工程”一词的体现。

上一节我们介绍了提示词工程的基本定义，本节中我们来看看它更广泛的含义。

提示词工程不仅仅是编写一条指令。它通常涉及将提示词整合到你的整个系统中。很多时候，事情并非简单地写一条提示词交给模型就结束了；实际上，情况要复杂得多。你可以将提示词视为一种“编程”模型的方式，尽管这听起来可能有些复杂。但正如扎克所说，清晰表达仍然是最重要的。

如果你将其视为编程，你就需要考虑数据来源、可访问的数据（例如在进行RAG时）、延迟权衡以及提供的数据量等因素。围绕模型构建系统需要大量的系统性思考，这也正是提示词工程值得作为一个独立领域来研究的原因。

那么，在这个意义上，提示词是“自然语言代码”吗？它是一种更高层次的抽象，还是一种完全不同的东西？

试图将提示词过度抽象化可能会让事情变得复杂。大多数时候，你只需要清晰地描述任务，而不是构建复杂的抽象结构。然而，你确实是在将一系列指令和内容“编译”成结果。在这个过程中，精确性、版本控制、实验管理以及实验跟踪等编程中需要考虑的因素，在提示词工程中同样至关重要。

现在，我们进入了一个奇怪的范式：一篇精心撰写的文章，看起来和代码是同类事物。但事实确实如此，我们现在撰写文章，却像对待代码一样处理它们。我认为这实际上是正确的。

## 如何成为一名优秀的提示工程师？

既然我们大致定义了提示词工程，那么什么造就了一名优秀的提示工程师呢？特别是在研究环境中，我们需要寻找具备哪些特质的人？

以下是成为一名优秀提示工程师所需的关键能力：

*   **清晰的沟通能力**：能够清晰地陈述事物、理解任务并出色地描述概念。这属于写作部分。然而，优秀的写作能力与优秀的提示工程师之间的关联性可能没有人们想象的那么强。
*   **迭代意愿**：人们常常认为写一次提示词就完成了。但实际上，为了得到一个还算不错的提示词，我可能会在15分钟内向模型发送数百条提示，不断来回调试。这种迭代的意愿，以及观察和思考“这里有什么被误解了”并加以修正的能力至关重要。
*   **预见性思维**：思考你的提示词可能出错的方式。如果你有一个要应用于400个案例的提示词，很容易只考虑典型情况，看到它在典型情况下得到正确答案后就继续前进。这是一个非常经典的错误。你真正需要做的是找到那些不寻常的案例。你必须思考你的提示词，并问自己：“在哪些情况下，连我自己都不清楚应该怎么做？”

例如，你有一个提示词说：“我会发送给你一些数据，我希望你提取所有名字以字母G开头的行。”然后你可能会发送一个根本没有以G开头名字的数据集，或者发送一个根本不是数据的东西，甚至发送一个空字符串。这些都是你必须尝试的案例，因为你需要知道模型在这些情况下会怎么做。然后，你可以为如何处理这些情况提供更多指令。

在与客户合作时，这种情况经常发生。工程师在构建某个东西时，会有一部分提示词是他们的客户将要填写的内容。他们总是设想用户会输入那些完美措辞的内容到聊天机器人中。但现实是，用户可能从不使用Shift键，每个单词都有拼写错误，没有标点，只是随机输入一些内容。工程师需要能够更进一步，推理出用户实际会尝试做什么，而不是只考虑理想情况。

你提到的一点让我深有共鸣：**阅读模型的输出**。在机器学习环境中，有一句近乎陈词滥调的话：“看看你的数据”。我认为在提示词工程中，对应的就是“看看模型的输出”。仔细阅读大量输出，近距离地阅读它们。例如，人们会在提示词中加入“逐步思考”，但却不去检查模型是否真的在逐步思考。模型可能会以更抽象或更笼统的方式来理解这个指令，而不是严格按照“你必须用这些特定标签写下你的想法”来执行。如果你不阅读模型的输出，你可能甚至不会注意到它犯了这样的错误。

这很有趣。这里确实存在一种奇怪的心理理论成分。作为一名提示工程师，你几乎必须思考模型将如何看待你的指令。但如果你是为企业用例编写提示词，你还必须思考用户将如何与模型交谈，你就像是坐在那里的第三方，处于一种奇怪的关系中。

关于心理理论部分，我想说的是：为一个任务写下指令是非常困难的。将你自己知道而克劳德不知道的所有信息从你的大脑中剥离出来，并清晰地传达给模型，这是一项极具挑战性的任务。我认为这是区分优秀和糟糕提示工程师的另一件事。

很多人只是写下他们知道的事情，但他们没有花时间系统地梳理出理解这个任务实际所需的完整信息集。我经常看到的一个奇怪现象是：某人写的提示词过于依赖于他们对任务的先验理解，以至于当他们展示给我看时，我会说：“这毫无意义。你写的这些词都没有意义，因为我对你有趣的用例一无所知。”

我认为，在这方面思考提示词工程的一个好方法，以及一项好技能，就是：**你能否真正从你所知的事物中退后一步，向这个知道很多但并非无所不知的奇怪系统传达它需要知道什么来完成一项任务？** 有多少次我看到某人的提示词，然后心想：“我无法根据这个提示词完成任务。我是人类水平，而你把这个交给一个比我差的东西，却期望它做得更好。” 是的，确实如此。

当前模型在回应时并不擅长提出好的探究性问题，就像人类会做的那样。如果我给扎克指示如何做某事，他会说：“这根本说不通。我这一步或这里应该做什么？” 模型不会这样做。所以你必须自己思考对方会说什么，然后回到你的提示词中回答那些问题。

## 与模型协作的技巧

你可以要求模型这样做。我最初处理提示词时首先做的事情之一就是：我会给它提示词，然后说：“我不希望你遵循这些指令，我只希望你告诉我这些指令在哪些地方不清晰、有任何歧义或者你不理解的地方。” 它并不总是完美的，但有趣的是，这是你可以做的一件事。

另外，有时如果人们看到模型犯了错误，他们不常做的一件事就是直接问模型。他们会问模型：“你这里弄错了，你能想想为什么吗？也许你能写一个我指令的修改版本，让你不再出错？” 很多时候，模型就能弄对。模型会说：“是的，这里不清楚，这是对指令的修正。” 然后你把这些修正放进去，它就奏效了。

我个人对此非常好奇：这是真的吗？这样有效吗？当模型出错时，你问它“你为什么出错了？”，然后它告诉你，也许还会说“未来我该如何措辞你才能做对？” 这里面有真实的成分吗？还是这只是模型围绕其认为的自身局限性产生的幻觉？

我认为，如果你向它解释它哪里错了，它有时能识别出问题。我认为这因任务而异。这是那种我不确定它有多少次能弄对的事情之一，但我总是尝试，因为有时确实有效。你总能学到一些东西。任何时候你与模型来回交流，你都能了解到正在发生什么。我认为，如果你至少不去尝试，你就是在放弃信息。

这很有趣。我打算再问你几个问题。

我们Anthropic公司有这些Slack频道，人们可以把克劳德加入Slack频道，然后通过它与克劳德交谈。阿曼达有一个Slack频道，很多人在那里关注她与克劳德的互动。我在那里看到你经常做的一件事（可能比Anthropic任何人都多）就是利用模型在各种不同场景中帮助你。我认为你在研究环境中非常信任模型。

我很好奇你是如何培养出这种直觉，知道何时可以信任模型。这不仅仅是使用经验的问题。

我认为我从不信任模型，然后我只是不断“敲打”它。所以你认为我经常那样做的原因，是因为那就像我在说：“我能信任你完成这个任务吗？” 因为有些事情，你知道模型有点奇怪。如果你稍微偏离分布，进入它们没有训练过的领域，或者遇到一些不寻常的情况，有时你会发现：“哦，实际上你在这里的可靠性要低得多，尽管这是一个相当简单的任务。” 我认为随着时间的推移，模型变得更好，这种情况发生得越来越少。但你想确保自己不在那种空间里。所以，是的，我不认为我默认信任它。

但在机器学习中，人们常常希望查看非常大的数据集。我在想：什么时候这样做有意义？我认为答案是：当每个数据点提供的信号相对较低时，你想查看许多许多数据点，因为你基本上想消除噪音。但对于很多提示任务，我认为你从每个查询中都能获得非常高的信号。因此，如果你有一套精心设计的几百条提示词，我认为这比几千条不那么精心构建的提示词能提供更多的信号。

在机器学习中，很多时候信号是数字，比如你是否预测对了某个东西。你可以尝试查看模型的log probs并凭直觉判断，但这有点不靠谱。

我觉得模型输出不仅仅是“对或错”的结果，更多时候是大量的文字内容。从它写的内容、原因和方式中，有太多根本性的东西可以学习。这就是提示词工程的一部分：不仅仅是它是否做对了任务，还有它是如何做到的？它经过了哪些思考步骤？通过阅读输出的细节，而不仅仅是结果，你可以了解到很多关于正在发生的事情的信息，或者至少可以尝试获得更好的理解。

此外，最出色的提示词工程有时能决定实验的成败。所以有时如果人们没有足够关注他们实验中的提示词部分，我会感到恼火。因为我认为，这实际上可能就是模型性能是前5%还是前1%或前0.1%的区别，从而决定你的实验是否成功。如果你花时间精心编写实验代码，却不在提示词上花时间，我觉得这说不通，因为那可能是你实验成败的关键。

在部署时也是如此。很容易出现“哦，我们无法发布这个”的情况，然后你稍微调整一下提示词，它就工作了。但这有点像一把双刃剑，因为我觉得在提示词工程中，总感觉地平线上有一个神话般的更好的提示词能解决我的问题。我看到很多人陷入这种“地平线上的神话提示词”的思维中，总觉得只要继续打磨，就能找到。但有时候，继续打磨提示词并不坏，正如我们讨论过的，你能学到东西。

但提示词工程令人害怕的一点是，存在一个充满未知的整个世界。你们有什么启发式方法来判断某件事通过完美的提示词（无论那可能是什么）是可能还是不可能实现的？

我通常检查模型是否“有点懂了”。对于那些我认为提示词无法提供帮助的事情，确实会有一点“打磨”，但通常很快就能清楚地看出它“差得远”或者根本不行。如果模型明显无法做某事，我不会在上面花费太长时间。你可以引导它思考，问它如何思考以及为什么，你可以大致感觉到它是否在正确的思路上。我们是否至少处于“可能正确”的邮政编码区域内？你可以在这方面获得一点“直觉”，感觉我正在朝着更接近正确的方向取得进展。

而有些任务，你根本无法取得任何进展。它的思维过程每次都会完全偏离到一个非常错误的方向。我倾向于放弃那些任务。不过，现在这样的任务非常罕见了。当我发现它们时，我会非常生气，因为它们太罕见了。我会暴怒：“竟然有任务是你无法通过我正确的引导来完成的？！”

我最近用克劳德玩《宝可梦》时就遇到了这种情况。那是我少有的几次，我向人们解释过，我觉得这很酷。我做了一个小实验，我把克劳德连接到一个Game Boy模拟器上，试图让它玩原版《宝可梦》游戏。它会思考想做什么，然后写一些代码来按下按钮，相当基础。我尝试了许多不同的、非常复杂的提示词布局，但你就是会陷入某些它根本无法做到的境地。

例如，向它展示一张Game Boy的截图，它真的无法理解。这让我非常沮丧，因为我习惯了它大多时候都能做点什么。我花了整整一个周末的时间，试图写出越来越好的提示词，让它真正理解这个Game Boy屏幕。我取得了一些渐进式的改进，从完全没有信号到有一些信号。但也就这样了，至少对我来说，这就像是一种启示。当我投入一个周末的时间，从没有信号到有一些信号，但仍然远未达到足够好的程度时，我就会想：“我就等下一个模型吧。再为这个打磨四个月，出来的东西会是另一个更好的模型。那才是更好地利用我的时间，在这期间做点别的。”

## 关于角色扮演与诚实沟通

这引出了一个有趣的观点。实际上，我想深入探讨一下，因为这是最著名的提示技巧之一：告诉语言模型它是某个角色或某种身份。

我觉得结果好坏参半。也许这在以前的模型中效果更好一些，现在可能没那么明显了。阿曼达，我总是看到你对模型非常诚实，比如“我是一名AI研究员，我在做这个实验。” 我会告诉它我是谁，比如“这是你在和谁说话”。你认为这种诚实程度，相对于对模型撒谎或强迫它（比如“我会给你500美元小费”），是更可取的方法吗？还是你对此有什么直觉？

我认为，随着模型能力更强，对世界理解更多，我觉得没有必要对它们撒谎。我一般也不喜欢对模型撒谎，因为我不喜欢撒谎。但部分原因是，如果你在构建一个机器学习系统或语言模型的评估数据集，那与为一些孩子构建测验是非常不同的。所以当人们做类似“我是一名老师，试图为测验想问题”这样的事情时，我会想：模型知道语言模型评估是什么。如果你问它不同的评估，它可以告诉你，并且可以给你提供它们看起来像什么的虚构例子，因为这些内容在互联网上，它们理解。所以我更愿意直接针对我实际拥有的任务。如果你说“我希望你构建看起来很像语言模型评估的问题”，那就是清晰沟通的问题。我想说：“事实上，这就是我想做的任务。那么，我为什么要假装我想做一些不相关或只是略微相关的任务，然后期望你以某种方式完成我实际想让你做的任务呢？”

我们不会对员工这样做。我不会去找一个和我一起工作的人说：“你是一名老师，你正在测验你的学生。” 我会说：“嘿，你在写那封邮件吗？” 我不知道。所以我认为，也许这是一种启发式方法。如果它们理解那件事，就直接要求它们做你想做的事。

我想稍微反驳一下。我发现有些情况下，虽然不是完全撒谎，但给它一个隐喻来思考问题会有所帮助。就像有时我可能不知道如何做某事，有人会说“想象一下你在做这个”，即使我知道我不是在做它。我想到的一个例子是：我试图让克劳德判断一张图表或图形的图像是好是坏，比如质量是否高。我为此找到的最好的提示词是问模型，如果这张图表作为高中作业提交，它会给出什么分数。

所以这并不是完全说“你是一名高中老师”，更像是“这是我希望你进行的分析类型，老师会使用的评分标准类似于我希望你使用的标准”。但我觉得这些隐喻仍然很难想出来，而且人们仍然经常默认使用任务的某种相似物，一些非常类似的任务。比如说你是一名老师，但你实际上会丢失很多关于你产品的细微差别。

我在企业提示词中经常看到这种情况，人们写一些类似的东西，因为他们有这种直觉，认为模型见过更多类似的东西，也许它见过更多高中测验，而不是语言模型评估。这可能是真的，但正如你所说，随着模型变得更好，我认为只是尝试非常规范地描述它们所处的确切情况，我经常给别人这个建议。这并不是说我认为在某些程度上这不是真的。

比如，像某人给图表评分的方式，就像他们给高中图表评分一样，也许这是真的。但人们经常尴尬地使用这个捷径来试图达到那个目的。所以我会尝试给出一个我可以实际谈论的例子，因为我觉得这很有趣。

比如写“你是一个有用的助手，正在起草一份文件”，对吧？这并不完全是你。比如，如果你在编写一个产品中的助手，告诉我你在产品中，告诉我我代表这家公司，我嵌入在这个产品中，我是该产品上的支持聊天窗口。你是语言模型，你不是人类，这没关系。但要非常规范地描述某物被使用的确切上下文。我发现很多情况下，因为我认为最常见的角色扮演是人们将其用作他们希望模型执行类似任务的捷径，然后当克劳德没有正确执行他们的任务时，他们会感到惊讶。但这不是你告诉它要做的任务。如果你没有提供关于你任务的细节，我觉得你遗漏了一些东西。

所以，是的，我不知道。虽然感觉像是一回事，但正如你关于模型规模的观点，也许过去确实如此，它们相对而言只对小学测验有很强的理解，但随着它们变得更聪明，能区分更多主题，我不知道。只是保持清晰。我觉得有趣的是，我从未使用过这种提示技巧，即使是面对更差的模型，我也从未发现它非常好用。

我觉得在“补全”时代的模型中，有一种关于将模型“调节”到有用的潜在空间的心理模型，我过去担心这个，但现在不太担心了。这可能是我从预训练模型到RLHF模型的直觉，对我来说没有意义。如果你在提示一个预训练模型，这对我来说是有意义的。有多少人试图将他们的直觉应用到……我认为这并不奇怪，大多数人并没有真正尝试过完整的预训练模型是什么，在你进行监督学习、RHF等之后会发生什么。

所以，当我与客户交谈时，他们总是试图映射一些东西：“哦，这在互联网上有多少？它们在互联网上见过很多这个吗？” 我认为这种直觉从根本上说是合理的，但正如你所说，当你真正开始写提示词时，它被过度应用了，因为到那时它们已经经历了所有其他实际上没有被建模的东西。

我觉得你应该尝试的第一件事是：我曾经给人们这个思想实验：想象你有一个任务，你雇佣了一家临时工中介派一个人来做这个任务。这个人到了，他们相当能干，对你的行业了解很多，但他们不知道你公司的名字，他们只是出现了，然后说：“嘿，我被告知你们有工作要我做，告诉我吧。” 然后你会对那个人说什么？你可能会使用这些隐喻，你可能会说：“我们想要这个，我们希望你检测好的图表。我们这里所说的好图表并不意味着它必须是完美的，你不需要去查所有细节是否正确，它只需要有坐标轴标签等等。所以想想高中水平的好图表。” 你可能会对那个人说完全一样的话。你不会对他们说“你是一名高中老师”，你会说“你是一名高中老师，正在阅读图表”。所以有时我只是想，是的，这就像……如果我读到它，我只是想，是的，想象这个人只有很少的上下文，但他们相当能干，他们理解很多关于世界的事情。尝试第一个版本，实际上假设他们可能知道关于世界的事情。如果那不起作用，你也许可以做调整。

很多时候，我尝试的第一件事就是那样，然后我就想，那刚刚就奏效了。然后人们会说：“哦，没想到直接告诉它所有关于我自己和我想要做的事情。” 我带着亚历克斯告诉我的这件事去找了那么多客户，他们说：“我的提示词不起作用，你帮我修复它。” 比如，你能描述一下任务吗？现在你刚才对我说的，就像语音报告一样，然后转录它，粘贴到提示词中，它比你原来的提示词更好。这有点像一种懒惰的捷径。
