# 构建AI智能体：1：核心概念与实用技巧 🧠

在本节课中，我们将学习AI智能体（Agent）的核心定义、它与工作流（Workflow）的区别，以及构建有效智能体的实用技巧。我们将通过简单的语言、公式和代码示例来阐明这些概念。

## 概述

AI智能体是当前的热门话题。我们将从Anthropic团队的实际经验出发，探讨智能体的本质、适用场景以及开发者应如何着手构建。核心在于理解智能体是让大型语言模型（LLM）自主决策并循环执行任务，直到问题解决。

---

## 什么是智能体？🤖

上一节我们概述了课程内容，本节中我们来看看智能体的具体定义。

关于“智能体”的定义有很多。在Anthropic的博客文章中，我们尝试将其与“工作流”区分开来。

*   **工作流**：由一系列预定义的LLM调用链组成。你知道需要多少步才能完成。
    *   **公式表示**：`输出 = 提示C(提示B(提示A(用户输入)))`
*   **智能体**：你让LLM自行决定运行多少次、采取哪些行动。它会循环运行，直到找到解决方案，步骤数量未知。
    *   **核心特征**：自主性、循环、工具使用。

**简单来说，智能体让LLM自己决定命运，而不是我们为它预先设定好路径。** 工作流则像是“在轨道上运行”，有固定的步骤。

---

## 工作流与智能体的实践区别 💻

理解了定义上的区别后，本节我们来看看在代码和提示词层面，它们具体有何不同。

这种区分源于模型能力的提升和团队实践的演变。我们从简单的单次LLM调用，发展到复杂的多步工作流，最终看到了能自我编排的智能体模式。

以下是两者在实现上的关键区别：

*   **工作流提示词**：每个提示词都非常具体，负责将一种输入转化为特定的输出。例如，第一个提示词将用户问题分类，第二个提示词则根据类别生成具体回复。
    *   **代码逻辑**：`输出A = llm_call(提示词A， 输入) -> 输出B = llm_call(提示词B， 输出A) -> 最终结果 = llm_call(提示词C， 输出B)`
*   **智能体提示词**：更加开放，通常为模型提供多种工具（如网络搜索、代码编辑），并指示它：“这是问题，你可以使用这些工具，持续操作直到找到答案。”

---

## 构建智能体的关键技巧 🛠️

在区分了工作流和智能体之后，构建一个有效的智能体需要注意哪些关键点呢？以下是来自实践的核心建议。

### 技巧一：具备模型同理心

设计智能体时，需要站在模型的角度思考。模型可能缺乏人类拥有的上下文和常识。

**一个有趣的故事**：在测试一个计算机操作基准时，我们一度无法理解模型的决策。于是我们模仿模型的“视角”——闭上眼睛一分钟，然后快速看一眼屏幕，再闭上眼思考“如果只能用Python代码操作这个环境，我会怎么做？”——突然间，模型的行为就变得合理了。

**给开发者的提示**：像模型一样看待世界，思考什么样的指令最清晰、最适用。

### 技巧二：精心设计工具描述

人们常会花费大量精力编写精美的提示词，却忽略了提供给模型的工具描述。

**常见问题**：工具文档简陋，参数名随意（如`a`, `b`），缺乏说明。这就像让工程师使用一个没有任何文档的函数一样困难。

**核心要点**：工具描述本身就是提示词的一部分。良好的工具描述能显著提升模型使用工具的效果。你需要像为人类编写API文档一样，为模型清晰地描述工具的功能、输入和输出。

## 智能体的现状：过度炒作与潜力所在 ⚖️

了解了构建技巧，我们来看看当前业界对智能体的普遍看法。哪些被高估了？哪些又被低估了？

### 被低估的潜力：节省时间，放大规模

即使只能为用户节省少量时间（比如一分钟），其价值也可能被低估。关键在于，自动化使得这项任务可以被轻松地重复执行十次、百次，从而显著扩大操作规模。

### 当前的成功甜蜜点

智能体在两类任务上表现尤为出色：
1.  **编码**：代码具有可验证性（通过单元测试）。智能体可以运行测试，根据错误反馈进行迭代，从而收敛到正确答案。
    *   **当前瓶颈**：现实世界中并非所有代码都有完美的单元测试。未来的关键在于为重要功能添加可验证的测试，让智能体能够自我检验。
2.  **搜索**：可以进行深度、迭代式的搜索。即使精度不够完美，也可以通过扩大召回范围再过滤的方式来获得有价值的信息。

### 被过度炒作的方向：消费者级全能智能体

目前，为普通消费者打造能处理复杂、高风险任务的智能体（例如“完全替我规划并预订一次度假”）可能为时过早。
*   **原因**：向智能体完整描述你的偏好和任务细节，其工作量可能接近于自己动手完成。同时，验证成本很高（你不可能不审核就让智能体直接订机票）。

**未来展望**：要达到这个目标，需要模型长期积累用户的上下文和偏好，这需要时间和过渡性产品。

## 给开发者的行动建议 🚀

展望了未来，最后我们为正在探索智能体的开发者提供一些切实可行的建议。

1.  **建立评估体系**：在构建之初，就必须有办法衡量结果。避免在真空中开发，却不知道产品是否有效，或者是否一个更简单的方案就能达到同样效果。
2.  **从简开始**：尽可能从一个简单的LLM调用开始，围绕它编写协调代码。这种代码逻辑即使模型能力提升后依然有价值。这样的产品能直接受益于未来模型的进步。
3.  **构建“模型越强，产品越好”的壁垒**：审视你的产品：如果模型变得更聪明，你的核心价值会消失吗？如果是，那可能方向错了。你应该构建的是，模型越强大，你的产品就变得越好的东西。
4.  **开始积累经验**：现在正是开始培养智能体思维、理解其能力边界的好时机。

## 总结

本节课中我们一起学习了：
*   **智能体**与**工作流**的核心区别在于自主决策和循环。
*   构建智能体需要**模型同理心**和**优秀的工具描述**。
*   智能体当前在**编码**和**搜索**等可验证或可容错的任务上最为有效。
*   开发者应**从简开始**，**建立评估标准**，并构建能随着模型能力增强而变得更强的产品。

现在，是时候开始你的智能体构建之旅了。
