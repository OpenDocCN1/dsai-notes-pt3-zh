# 062：语义过滤模式 🧠

在本节课中，我们将学习大型语言模型（LLM）的一个核心应用模式——语义过滤。这种模式能够理解文本的含义，并根据我们设定的语义规则，从文本中移除或保留特定信息。

大型语言模型非常擅长处理文本和理解语言模式。很多时候，文本分析工作非常困难，因为过去我们需要人工审阅才能进行高质量的分析。如今，我们可以利用大型语言模型来完成这项任务。处理和操控文本是大型语言模型的真正优势之一。

上一节我们介绍了LLM处理文本的基本能力，本节中我们来看看一种具体的应用模式。

## 什么是语义过滤？ 🔍

语义过滤本质上是一种过滤器，它可以接收文本，并根据文本的含义或我们指定的特定属性，从中移除信息或仅保留符合条件的信息。

这种模式在多种场景下都非常有用。接下来，我将展示一个案例：对文本进行过滤，移除我们希望删除的特定内容。这些内容可能是某种机密信息、非公开内容、冗余信息等。这是一个用于处理和操控文本的实用模式。

## 示例一：过滤日期 📅

让我们看一个语义过滤的简单示例。

我将创建一个复杂的过滤器，其任务是：接收信息，移除所有日期，并为了修复因移除日期而可能造成的语句不通顺问题，对文本进行最小程度的改写。

以下是使用的提示词示例：
```
filter this information to remove all dates and rewrite the text as little as possible to fix issues caused by the date removals.
```

然后，我粘贴了一段来自维基百科的关于范德堡大学的介绍文本，其中包含许多日期。

通过使用“filter this information”这样的指令，我们清晰地表明意图是进行过滤操作——保留主体内容但移除特定部分，而非创造新内容。语义过滤模式的核心是：指示模型进行过滤，并提供基于语义的规则，即我们希望移除的信息的含义或目的。

模型执行后，会重写所有文本。可以看到，它做得很好，移除了所有明确的日期。不过，我注意到可能需要重新思考如何定义“日期”。例如，原文是“founded in 1873”，模型将其改写为“founded in the 19th century”。这表明模型对“日期”进行了字面理解（具体的年月日），并进行了语义转换。这个例子展示了模型的能力：它理解文本，理解什么是日期，将其移除，并在此过程中进行了一定的改写。

## 示例二：过滤敏感医疗信息 🏥

现在，让我们看一个更能体现语义理解的、更有趣的例子。

我将要求模型过滤以下信息，移除任何可能帮助他人推断出患者患有糖尿病的信息。首先，请解释你将移除哪些信息以及这些信息如何帮助推断；然后，提供过滤后的信息。

以下是使用的提示词示例：
```
filter the information below to remove any information that would help someone figure out that the patient has diabetes. First, explain what information you're going to remove and how it might help someone figure out that the patient has diabetes, then provide the filtered information.
```

我提供了一份虚构的病历，描述了患者Jane Doe，包含一系列症状、现病史、既往史、用药史等信息。

模型随后分析了需要移除的内容：
*   **主诉**：“口渴加重和疲劳”应被移除，因为多饮（口渴加重）是糖尿病的常见症状。
*   **现病史**：提及“口渴加重”和“未检查血糖水平”的部分应被移除，因为它们与糖尿病症状和管理相关。
*   **既往史**：“2型糖尿病”应被移除，因为它直接表明患者患有糖尿病。
*   **用药**：“二甲双胍1000毫克，每日两次”应被移除，因为二甲双胍是常用于治疗糖尿病的药物。

这个过程应用了语义规则：我希望过滤掉可能泄露患者患有糖尿病的信息。模型必须在一定程度上理解文本的含义，或者基于其训练数据，识别出这些与糖尿病相关的常见讨论内容。

接着，模型重写了病历。例如，主诉被改写为“患者因过去两周疲劳就诊”，现病史和用药部分也做了相应修改。这样，我们就得到了一份过滤后的病历。

## 语义过滤的潜力与局限 ⚖️

我们可以利用大型语言模型，通过语义过滤模式开发出强大的语义过滤器。

然而，它完美吗？并不。正如我们所看到的，它可能存在一些问题。并且正如之前讨论过的，模型的输出并非总是完全可重复的。但它可以作为一个起点，辅助人工审核流程进行二次检查，或帮助防止信息意外泄露。它是系统中的又一道检查关卡。

这是一项成本相对较低的检查，用于尝试移除额外信息。它应该是唯一的检查手段吗？不。如果我们要过滤信息，尤其是出于隐私或其他原因不希望泄露的信息，我们始终应该设置其他检查措施。因为这不会是一个完美的过滤器，它具有一定随机性，不会总是完全符合我们的预期。

但是，作为另一个流程的组成部分，作为一种辅助工具，这是一项非常强大的技术。我们可以将其与其他检查、其他类型的移除方法并行或结合使用。

本节课中，我们一起学习了语义过滤模式。我们了解到，大型语言模型能够理解文本的语义，并根据我们设定的规则（例如“移除所有日期”或“移除可能暗示疾病的信息”）对文本进行过滤和改写。这种模式在数据清洗、隐私保护、信息摘要等多种场景下具有实用价值。同时，我们也认识到，由于模型可能存在的不确定性和不完美性，它更适合作为辅助工具，与其他方法结合使用，而非唯一的解决方案。
