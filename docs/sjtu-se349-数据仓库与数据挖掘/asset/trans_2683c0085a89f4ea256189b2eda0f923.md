## 数据预处理的主要任务

- 数据集成 Data integration
  - 关于顾客标识的属性在一个数据库中可能是 Custom_ID，而在另一个中为 Cust_ID
  - 同一个人的名字可能在第一个数据库中登记为“ Bill”，在第二个数据库中登记为“ William ”，而在第三个数据库中登记为“ B ”
  - 有些属性可能是由其他属性导出的（例如，年收入），冗余数据可能降低数据挖掘过程的性能或使之陷入混乱

## 数据预处理的主要任务

- 数据规约 Data reduction：得到数据集简化表示，小得多，但能够产生同样的（或几乎同样的）分析结果
  - 维规约 Dimensionality reduction
    - 使用数据编码方案，以便得到原始数据的简化或“压缩”表示
    - 数据压缩技术（例如，小波变换和主成分分析）
    - 属性子集选择（去掉不相关的属性）
    - 属性构造（从原来的属性集导出更有用的小属性集）
  - 数值规约 Numerosity reduction
    - 使用最近邻分类或聚类这样的基于距离的挖掘算法进行分析
    - 顾客数据包含年龄和年薪属性，年薪属性的取值范围可能比年龄大得多，如果属性未规范化，则距离度量在年薪上所取的权重一般要超过距离度量在年龄上所取的权重
    - 如果待分析的数据已经规范化，即按比例映射到一个较小的区间（例如，[0.0, 1.0]），则这些方法将得到更好的结果

## 数据预处理的主要任务

数据离散化和概念分层

## 数据清理 Data Cleaning

- 现实世界的数据一般都是脏的：许多潜在的不正确的数据，例如，由设备故障、人或电脑出错、传输错误引起的
  - 数据有缺失 incomplete: 缺少属性值或者某些感兴趣的属性，或仅包含聚集数据
    - e.g., *Occupation* = “ ” (missing data)
  - 噪声数据 noisy: 包含错误或存在偏离期望的值
    - e.g., *Salary* = “−10” (an error)
  - 不一致 inconsistent: 在编码或名称上存在差异, e.g.,
    - *Age* = “42”, *Birthday* = “03/07/2010”
    - Was rating “1, 2, 3”, now rating “A, B, C”
    - 重复的记录有出入
  - 人为因素 Intentional (e.g., *disguised missing data*)
    - Jan. 1 as everyone’s birthday?

## 缺失值 Incomplete (Missing) Data

- 并不是在所有情况下都能获取数据
  - E.g., 许多数据缺乏某些属性，比如销售数据中，顾客的收入数据
- 缺失值可能是因为
  - 设备故障
  - 不符合其他记录的数据，从而删除
  - 由于无解，数据未被输入
  - 在输入数据的时候某些数据被认为是不重要的
  - 数据变化而缺乏历史记录
- 丢失的数据可能需要被推断

## 如何处理缺失值？

- 忽略元组 Ignore the tuple: 当缺少类标号时通常这样做（假设挖掘任务涉及分类）—当每个属性缺失值的百分比变化很大时，它的性能很差

- 人工填写缺失值: 费事 + 不可行？

- 使用一定的内容填充
  —全局常量: e.g., “unknown”, a new class?!
  —使用属性的中心度量（如均值或中位数）
  —使用与给定元组属同一类的所有样本的属性均值或总位数: 更科学
    - 如果将顾客按风险等级分类，则用具有相同信用风险的顾客的平均收入替换缺失值
  —使用最可能的值: 使用回归、贝叶斯形式化的方法或者决策树等基于推理的工具

## 噪声数据 Noisy Data

- **噪声 Noise**: 被检测的变量的随机误差或方差
- **不正确的属性值** 可能是因为
  - 错误的数据收集工具
  - 数据输入的问题
  - 数据传输问题
  - 技术限制
  - 不一致的命名惯例
- **这些数据问题** 也需要数据清洗
  - 重复记录
  - 数据不完整
  - 数据不一致

## 数据清理作为一个过程

## 第1步：偏差检测 Data discrepancy detection

— 导致偏差的因素可能有多种

- 具有很多可选字段的输入表单
- 人为的数据输入错误
- 有意的错误（例如，不愿意泄露自己的信息）
- 数据退化（例如，过时的地址偏差）
- 不一致的数据表示和编码的不一致使用
- 记录数据的设备的错误和系统错误
- 数据（不适当地）用于不同于当初的目的时，也可能出现错误
- 数据集成也可能导致不一致（例如，当给定的属性在不同的数据库中具有不同的名称时）

— 偏差检测方法

- 使用元数据 metadata (e.g., 数据定义域、数据值域、数据的依赖、数据的分布)
- 检查字段过载 field overloading
  - 开发者将新属性的定义挤进已经定义的属性的未使用（位）部分（如，使用一个属性未使用的位，该属性取值已经使用了32位中的31位）
- 检查唯一性规则 uniqueness rule、连续性规则 consecutive rule 和空值规则 null rule
  - 唯一性规则是说给定属性的每个值都必须不同于该属性的其他值
  - 连续性规则是说属性的最低和最高值之间没有缺失的值，并且所有的值还必须是唯一的
  - 空值规则应当说明如何记录空值条件，例如数值属性存放0，字符属性存放空白或其他使用方便的约定（诸如“不知道”或“？”这样的项应转换成空白）
