

## 基于约束的聚类方法 (I)：
处理硬约束

- 处理硬约束：严格遵守聚类分配中的约束
- 示例：COP-k-means 算法
  - 为 must-link 约束生成超实例
    - 计算 must-link 约束的传递闭包
    - 为了表示这样的子集，用均值替换子集中所有对象。
    - 超实例还携带一个权重，即其代表的对象数量
  - 执行修改后的 k-means 聚类以遵守 cannot-link 约束
    - 将 k-means 中的中心分配过程修改为 *最近可行中心分配*
    - 一个对象被分配到最近的中心，使得分配遵守所有 cannot-link 约束

## 基于约束的聚类方法 (II)：
处理软约束

- 被视为一个优化问题：当聚类违反软约束时，对聚类施加惩罚
- 总体目标：优化聚类质量，并最小化约束违反惩罚
- 例：CVQE（Constrained Vector Quantization Error）算法：在执行 k-means 聚类时强制执行约束违反惩罚
- 目标函数：k-means 中使用的距离之和，根据约束违反惩罚进行调整

- must-link 违反的惩罚
  - 如果对象 x 和 y 必须链接但它们被分配到两个不同的中心 c₁ 和 c₂，则 dist(c₁, c₂) 会作为惩罚添加到目标函数中

- cannot-link 违反的惩罚
  - 如果对象 x 和 y 不能链接但它们被分配到一个共同中心 c，则 dist(c, c′)，c 与 c′ 之间的距离会作为惩罚添加到目标函数中，其中 c′ 是可以容纳 x 或 y 的离 c 最近的簇

## 加速约束聚类

- 计算某些约束聚类成本高昂
- 例：带障碍物对象的聚类：Tung, Hou, and Han. Spatial clustering in the presence of obstacles, ICDE'01
- K-medoids 更可取，因为 k-means 可能将 ATM 中心定位在湖泊中间
- 可视性图和最短路径
- 三角剖分和微聚类
- 两种值得预计算的连接索引（最短路径）
  - VV 索引：任意一对障碍顶点 的索引
  - MV 索引：任意一对微簇和障碍索引 的索引

用户提示

所有用于聚类的元组

用户指定的特征（以属性形式）被用作提示，而不是类标签

- 该属性可能包含太多或太少的不同值，例如，用户可能希望将学生聚类为 20 个簇而不是 3 个
- 需要在聚类分析中包含其他特征

## 与半监督聚类比较

- 半监督聚类：用户提供一个训练集，由“相似”（“must-link”）和“不相似”（“cannot link”）的对象对组成
- 用户引导聚类：用户指定一个属性作为提示，并为聚类找到更相关的特征
