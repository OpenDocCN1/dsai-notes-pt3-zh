    - The chance to pick up a particular set of 10 products: ~10⁻⁴⁰
    - What is the chance this particular set of 10 products to be frequent 10³ times in 10⁹ transactions?

## Apriori: 通过限制候选产生发现频繁项集

- Apriori 美['eɪpri'ɔːrɪ] adj.<拉>由原因推及结果的;演绎的;先验的;推测的

- Apriori剪枝原则: If there is any itemset which is infrequent, its superset should not be generated/tested! (Agrawal & Srikant @VLDB’94, Mannila, et al. @ KDD’94)

- 方法:
  - 最初，一次扫描数据库得到频繁1-项集
  - 从长度为k的频繁项集中生成长度（k+1）的候选项集
  - 根据数据测试候选项集
  - 当没有频繁或候选集生成时，算法结束

(a) 连接：C₃ = L₂ ⋈ L₂ = {{11, 12}, {11, 13}, {11, 15}, {12, 13}, {12, 14}, {12, 15}} ⋈ {{11, 12}, {11, 13}, {11, 15}, {12, 13}, {12, 14}, {12, 15}} = {{11, 12, 13}, {11, 12, 15}, {11, 13, 15}, {12, 13, 14}, {12, 13, 15}, {12, 14, 15}}

(b) 使用先验性质剪枝：频繁项集的所有非空子集必须是频繁的。是否存在候选项集，其子集不是频繁的吗？

- {11, 12, 13} 的 2 项子集是 {11, 12}、{11, 13} 和 {12, 13}。{11, 12, 13} 的所有 2 项子集都是 L₂ 的元素。因此，{11, 12, 13} 保留在 C₃ 中。
- {11, 12, 15} 的 2 项子集是 {11, 12}、{11, 15} 和 {12, 15}。{11, 12, 15} 的所有 2 项子集都是 L₂ 的元素。因此，{11, 12, 15} 保留在 C₃ 中。
- {11, 13, 15} 的 2 项子集是 {11, 13}、{11, 15} 和 {13, 15}。{13, 15} 不是 L₂ 的元素，因而不是频繁的。因此，从 C₃ 中删除 {11, 13, 15}。
- {12, 13, 14} 的 2 项子集是 {12, 13}、{12, 14} 和 {13, 14}。{13, 14} 不是 L₂ 的元素，因而不是频繁的。因此，从 C₃ 中删除 {12, 13, 14}。
- {12, 13, 15} 的 2 项子集是 {12, 13}、{12, 15} 和 {13, 15}。{13, 15} 不是 L₂ 的元素，因而不是频繁的。因此，从 C₃ 中删除 {12, 13, 15}。
- {12, 14, 15} 的 2 项子集是 {12, 14}、{12, 15} 和 {14, 15}。{14, 15} 不是 L₂ 的元素，因而不是频繁的。因此，从 C₃ 中删除 {12, 14, 15}。

(c) 因此，剪枝后 C₃ = {{11, 12, 13}, {11, 12, 15}}。

## Apriori算法(伪代码)

C_k: 长度为k的候选集

L_k: 长度为k的频繁项集

```
L_1 = {频繁项};
for (k = 1; L_k != ∅; k++) do begin
    C_{k+1} = 从L_k生成候选集;
    for each 数据库中的事务 t do
        增加所有C_{k+1} 中t包含的候选集的count
    L_{k+1} = C_{k+1} 中大于min_support的候选集
end
return ∪_k L_k;
```

## Apriori实现

- 如何生成候选项集？
  - Step 1: 连接步 L_k
  - Step 2: 剪枝步

- Example of Candidate-generation
  - L₃={abc, abd, acd, ace, bcd}
  - Self-joining: L₃*L₃
    - abcd from abc and abd
    - acde from acd and ace
  - Pruning:
    - acde is removed because ade is not in L₃
  - C₄ = {abcd}

## 候选集生成: An SQL Implementation

- 候选集生成的SQL 实现
  - Suppose the items in $L_{k-1}$ are listed in an order
  - Step 1: self-joining $L_{k-1}$
    ```sql
    insert into $C_k$
    select p.item$_1$, p.item$_2$, ..., p.item$_{k-1}$, q.item$_{k-1}$
    from $L_{k-1}$ p, $L_{k-1}$ q
    where p.item$_1$=q.item$_1$, ..., p.item$_{k-2}$=q.item$_{k-2}$, p.item$_{k-1}$ < q.item$_{k-1}$
    ```
  - Step 2: pruning
    forall itemsets c in $C_k$ do
    forall (k-1)-subsets s of c do
    if (s is not in $L_{k-1}$) then delete c from $C_k$
- Use object-relational extensions like UDFs, BLOBs, and Table functions for efficient implementation [See: S. Sarawagi, S. Thomas, and R. Agrawal. Integrating association rule mining with relational database systems: Alternatives and implications. SIGMOD’98]
