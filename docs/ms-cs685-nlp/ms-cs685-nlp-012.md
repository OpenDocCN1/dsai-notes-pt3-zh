# 📚 课程 P12：L9 - 下游任务迁移学习

在本节课中，我们将要学习如何利用其他有标签的数据集来提升特定下游任务的性能，这种方法被称为**中间任务微调**。我们将探讨其基本概念、与传统多任务学习的区别，并介绍一种通过任务嵌入来选择最佳中间任务的方法。

## 🎯 概述：从预训练到下游任务

我们之前学习的范式是：首先在大规模无标签数据上预训练一个模型（如 BERT），然后在特定的下游任务（如 SQuAD 问答数据集）上进行微调。这个过程可以表示为：

**预训练 → 下游任务微调**

然而，我们通常还拥有许多其他有标签的数据集。一个自然的问题是：能否利用这些数据集来提升我们关心的下游任务（例如 SQuAD）的性能？

---

## 🔄 多任务学习：一种直观的方法

一种直观的方法是**多任务学习**。在微调阶段，我们不仅使用目标数据集（如 SQuAD），还将其他相关数据集（如 HotpotQA、NewsQA）的样本混合在一起进行训练。

以下是多任务学习的损失函数示例，它通过权重 λ 来平衡不同任务的损失：

`L_total = λ * L_squad + (1 - λ) * L_hotpotqa`

其中 λ 是一个介于 0 和 1 之间的超参数。如果我们更关心 SQuAD 的性能，可以将 λ 设置得较高（例如 0.8）。

然而，多任务学习存在挑战：
*   如何为不同任务选择合适的权重 λ？
*   随着任务数量增加，权重调整变得非常困难。
*   在实践中，简单的等权重多任务学习通常难以带来显著的性能提升。

## 🚀 中间任务微调：分阶段的方法

![](img/e996e93a8a3b5c4ef30008591fbba5d8_18.png)

![](img/e996e93a8a3b5c4ef30008591fbba5d8_20.png)

为了规避多任务学习的复杂性，我们引入**中间任务微调**。这种方法在预训练和最终的下游任务微调之间，插入了一个额外的微调阶段。

新的流程变为：
**预训练 → 中间任务微调 → 下游任务微调**

例如：
1.  在无标签数据上预训练 BERT。
2.  在 HotpotQA 数据集上对 BERT 进行微调，得到一个中间模型。
3.  在 SQuAD 数据集上对这个中间模型进行再次微调，得到最终模型。

![](img/e996e93a8a3b5c4ef30008591fbba5d8_22.png)

![](img/e996e93a8a3b5c4ef30008591fbba5d8_24.png)

这相当于将多任务学习的动态权重调整简化为两个极端阶段：先 100% 专注于中间任务，再 100% 专注于下游任务。

---

## ❓ 核心问题：如何选择中间任务？

中间任务微调的效果很大程度上取决于所选的中间任务。选择不当甚至可能损害下游任务的性能。因此，核心问题是：**给定一个下游任务，如何从众多候选任务中预测出最能提升其性能的中间任务？**

![](img/e996e93a8a3b5c4ef30008591fbba5d8_26.png)

影响任务选择效果的因素可能包括：
*   **任务相似性**：中间任务与下游任务在格式和所需推理能力上是否相似？（例如，QA 任务对 QA 任务）
*   **数据集大小**：中间任务的数据集规模是否足够大？
*   **领域相似性**：中间任务与下游任务的数据来源领域是否相近？（例如，都来自维基百科）

## 🧠 任务嵌入：量化任务关系

![](img/e996e93a8a3b5c4ef30008591fbba5d8_30.png)

为了系统地选择中间任务，我们可以尝试将每个任务表示为一个低维向量，即**任务嵌入**。我们希望在这个嵌入空间中，相似的任务彼此靠近。

一种方法是利用模型在微调过程中的信息。具体来说，对于一个任务，我们可以：
1.  在预训练模型（如 BERT）上对其进行微调。
2.  计算**经验费舍尔信息矩阵**，该矩阵量化了模型各个参数对任务损失变化的重要性。
3.  从这些信息中提取并聚合出一个固定维度的向量，作为该任务的嵌入。

![](img/e996e93a8a3b5c4ef30008591fbba5d8_32.png)

通过这种方式，我们可以为任务库中的每个任务计算一个嵌入。

![](img/e996e93a8a3b5c4ef30008591fbba5d8_34.png)

---

## 🎯 基于任务嵌入选择中间任务

![](img/e996e93a8a3b5c4ef30008591fbba5d8_36.png)

当我们获得一个新下游任务时，可以：
1.  使用上述方法计算该下游任务的嵌入。
2.  在任务嵌入空间中，找到与下游任务嵌入最接近的现有任务。
3.  将这个最近邻任务作为中间任务，进行中间任务微调流程。

![](img/e996e93a8a3b5c4ef30008591fbba5d8_38.png)

这种方法提供了一种数据驱动的方式来选择中间任务，而无需对每个候选任务都进行昂贵的端到端实验。

![](img/e996e93a8a3b5c4ef30008591fbba5d8_40.png)

## 📊 实验结果与启示

![](img/e996e93a8a3b5c4ef30008591fbba5d8_42.png)

研究显示：
*   对于大多数下游任务，都存在能显著提升其性能的中间任务。
*   任务嵌入方法选择的中间任务通常优于随机选择，并能带来稳定增益。
*   结果有时符合直觉（例如，QA 任务受益于其他 QA 任务），但也存在反直觉的情况（例如，某些序列标注任务能极大帮助特定的 QA 任务），其深层原因尚不完全清楚。
*   在**低资源下游任务**（训练数据少）的场景下，中间任务微调带来的提升尤为明显。
