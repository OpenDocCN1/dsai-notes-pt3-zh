## 🎯 L1- 知识图谱简介

知识图谱是一种用于表示和存储知识的图结构数据模型。它由**实体**、**关系**和**属性**构成，能够以结构化的方式描述现实世界中的事物及其联系。

一个基本的知识图谱三元组可以表示为：`(头实体, 关系, 尾实体)`。

## 🔍 L2- 知识图谱的What和Why

上一节我们介绍了知识图谱的基本概念，本节中我们来看看知识图谱是什么以及为什么需要它。

知识图谱的核心价值在于将非结构化的信息转化为机器可理解和可推理的结构化知识。它能够支持语义搜索、智能问答和复杂推理等高级应用。

以下是知识图谱的几个关键作用：

*   **增强搜索能力**：理解用户查询的意图，返回更精准的结果。
*   **支持推理**：基于已有事实推导出新的事实。
*   **数据集成**：将来自不同来源的数据统一到一个连贯的模型中。

## 🧱 L3- 图数据模型

图数据模型是知识图谱的基石。它使用节点和边来表示数据，其中节点代表实体，边代表实体之间的关系。

一个简单的图可以用邻接表或邻接矩阵来表示。在代码中，一个基础的图结构可以这样定义：

```python
class Graph:
    def __init__(self):
        self.nodes = {}  # 节点字典：{节点ID: 节点属性}
        self.edges = []  # 边列表：[(源节点, 关系, 目标节点), ...]
```

## 💬 L4.1- 应用Cypher进行图谱查询

Cypher是Neo4j图数据库的声明式查询语言，它使用一种直观的、基于模式的语法来查询和操作图数据。

一个典型的Cypher查询模式如下：

```
MATCH (p:Person)-[:LIVES_IN]->(c:City)
WHERE c.name = '北京'
RETURN p.name
```

这条查询的意思是：找到所有居住在“北京”这个城市的人，并返回他们的名字。

## 🌐 L4.2- 分布式RDF数据管理与查询

RDF是资源描述框架的缩写，是表示知识图谱信息的标准数据模型。它使用三元组的形式存储数据。

一个RDF三元组通常表示为：`<主语> <谓语> <宾语>`。

例如：`<张三> <住在> <北京>`。

在处理大规模RDF数据时，需要使用分布式系统（如Apache Jena, Virtuoso）来存储和查询，以应对海量数据带来的挑战。

## 📐 L5- 如何设计知识图谱Schema

Schema（模式）为知识图谱定义了数据结构和约束，相当于关系数据库中的表结构。一个好的Schema设计是构建高质量知识图谱的前提。

设计Schema时，需要明确以下核心要素：

*   **实体类型**：如人物、地点、组织。
*   **关系类型**：如“出生于”、“就职于”。
*   **属性**：如人物的“姓名”、“出生日期”。
*   **约束**：如一个人物必须有一个姓名属性。

## 🏗️ L6.1- 把维基百科数据构建成维基知识库

维基百科是一个丰富的半结构化数据源，非常适合用于构建大规模知识图谱。其信息框、分类和链接结构包含了大量实体和关系信息。

构建过程通常包括以下步骤：

1.  **数据抽取**：从维基百科的XML dump文件中提取页面、信息框、链接等信息。
2.  **实体识别与链接**：将文本中的提及链接到知识库中的具体实体。
3.  **关系抽取**：从信息框和正文中抽取出实体之间的关系。
4.  **知识融合**：将抽取出的知识与现有知识库进行合并，解决冲突和重复。

## 🦠 L6.2- 给维基数据添加Convid信息

在特定领域（如公共卫生），需要为通用知识图谱补充专业信息。例如，在COVID-19疫情期间，可以向维基数据中添加病毒、药物、病例数等相关实体和属性。

这个过程展示了知识图谱的可扩展性，能够动态地吸收和整合新的知识。

## 🧬 L6.3- 维基数据中的实体Schema和形状语言

维基数据使用一套严格的Schema（称为“本体”）来定义其实体类型和属性。形状语言（如SHACL）则用于表达对数据的约束和验证规则。

例如，可以定义一个形状来约束“城市”实体必须具有“坐标”和“人口”属性。

## 🗃️ L7- 如何从结构化数据中构建知识图谱

结构化数据（如关系型数据库、CSV文件）是构建知识图谱最直接的数据源。转换过程通常涉及将表映射为实体，将外键关系映射为图谱关系。

以下是主要的映射规则：

*   **表 -> 实体类型**
*   **表的行 -> 实体实例**
*   **表的列 -> 属性**
*   **外键 -> 关系**

## 🤖 L8.1- 自监督实体识别与消歧

从非结构化文本（如新闻、报告）中构建知识图谱，首先需要识别文本中提到的实体。自监督学习利用知识图谱本身作为监督信号，训练模型来识别新文本中的实体。

实体消歧是指将文本中提到的模糊名称（如“苹果”）确定到知识图谱中唯一的实体（是“苹果公司”还是“水果苹果”）。

## 🔗 L8.2- 网络知识图谱中的指代消解

指代消解是解决文本中代词（如“他”、“它”）或别称指向哪个实体的问题。这对于理解长文本和构建连贯的知识图谱至关重要。

例如，在句子“马云创立了阿里巴巴。他是一位企业家。”中，需要将“他”消解到实体“马云”。

## 📖 L9- 如何从文本数据中构建知识图谱

本节综合前两节内容，系统介绍从纯文本构建知识图谱的完整流程。

流程主要包括以下步骤：

1.  **命名实体识别**：识别文本中的人名、地名、组织名等。
2.  **关系抽取**：识别实体之间的关系，如“创立”、“位于”。
3.  **实体链接**：将识别出的实体链接到知识库中的标准实体。
4.  **知识融合**：将新抽取的知识与现有图谱合并。

## ⚙️ L10.1- 构建用于语言理解的因果知识图谱

因果知识图谱不仅描述事物“是什么”，还描述“为什么”以及“如何导致”。这对于深度语言理解、解释性AI和决策支持系统非常重要。

一个因果关系的三元组可能表示为：`<吸烟> <导致> <肺癌>`，并可能带有置信度或证据。

## 🖼️ L10.2- 可用于图像理解的场景图谱

场景图谱将计算机视觉与知识图谱结合，用于描述图像中的场景。它不仅识别物体，还识别物体之间的关系和属性。

例如，一张图片的场景图谱可能包含：`(男人, 正在骑, 自行车)`，`(自行车, 颜色, 红色)`。

## 🧠 L11.1- 知识图谱知识推理算法介绍

知识推理旨在利用图谱中已有的知识，推导出未明确存储的新知识或发现隐藏的关系。

以下是几种常见的推理方法：

*   **基于规则的推理**：使用预定义的逻辑规则进行推导。
    *   例如：`IF (A, 父亲, B) AND (B, 父亲, C) THEN (A, 祖父, C)`
*   **基于嵌入的推理**：将实体和关系映射到低维向量空间，通过向量运算进行推理。
    *   例如 TransE 模型的目标是使 `h + r ≈ t`（头实体向量 + 关系向量 ≈ 尾实体向量）。
*   **基于路径的推理**：考虑实体间的多跳路径来预测关系。

## 💎 L11.2- 知识图谱的高价值应用案例介绍

知识图谱已在众多领域产生巨大价值。

*   **推荐系统**：利用用户、物品及丰富属性图谱，实现更精准的个性化推荐。

例如，将问题“Who founded Microsoft?” 转换为逻辑查询：`?x : founded(?x, Microsoft)`。

## 🌱 L16.1- 如何拓展知识图谱

知识图谱需要持续增长。拓展方式包括：

*   **横向拓展**：增加新的实体和关系实例。
*   **纵向拓展**：增加新的实体类型和关系类型（即Schema演化）。
*   **深度拓展**：为现有实体添加更丰富的属性和关系。

## 📈 L16.2- 针对递归查询的增量视图维护

在大规模图谱中，某些复杂查询（如查找所有间接持股关系）可能非常耗时。增量视图维护技术可以在数据更新时，只计算和更新受影响的那部分查询结果，从而保证查询效率。
