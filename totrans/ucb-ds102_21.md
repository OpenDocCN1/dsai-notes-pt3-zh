Neural nets are a very powerful class of methods that have become popular in fields like computer vision and natural language processing, where coming up with good features can be challenging.

While there’s a rich mathematical foundation underlying neural nets, in this class we’ll focus on one of the big computational ideas that’s at the heart of most neural net implementations: backpropagation and automatic differentiation. While these ideas were initially conceived for neural nets, they’re now used in many other ways too: libraries like PyMC use automatic differentiation to do efficient Bayesian inference; and much more.

In general, automatic differentiation and backpropagation are useful for any problem where the solution involves computing gradients!

## A feed-forward neural network[¶](#a-feed-forward-neural-network "Link to this Section")

As we’ve already seen, linear regression is a simple but powerful model: to predict a value <semantics><mrow><mi>y</mi></mrow><annotation encoding="application/x-tex">y</annotation></semantics>y from a vector of features <semantics><mrow><mi>x</mi><mo>=</mo><mo stretchy="false">(</mo><msub><mi>x</mi><mn>1</mn></msub><mo separator="true">,</mo><mo>…</mo><mo separator="true">,</mo><msub><mi>x</mi><mi>k</mi></msub><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">x = (x_1, \ldots, x_k)</annotation></semantics>x=(x1​,…,xk​), linear regression uses the following:

<semantics><mrow><mi>y</mi><mo>=</mo><mi>W</mi><mi>x</mi><mo>+</mo><mi>b</mi></mrow><annotation encoding="application/x-tex">y = Wx + b</annotation></semantics>y=Wx+b[(1)](#NDJrX1ikVo "Link to this Equation")

Here, <semantics><mrow><mi>W</mi></mrow><annotation encoding="application/x-tex">W</annotation></semantics>W is a vector of coefficients, sometimes also called **weights**, and <semantics><mrow><mi>b</mi></mrow><annotation encoding="application/x-tex">b</annotation></semantics>b is a scalar that we call the intercept or bias. As we saw in the previous section, linear models can fail when the relationship between <semantics><mrow><mi>x</mi></mrow><annotation encoding="application/x-tex">x</annotation></semantics>x and <semantics><mrow><mi>y</mi></mrow><annotation encoding="application/x-tex">y</annotation></semantics>y is nonlinear. We also saw that if we want to model complex, nonlinear interactions *while still using linear models*, we need to define more complex features.

Motivated by this, what if we tried using another layer of linear regression that could compute features for us? It might look something like this:

<semantics><mrow><mi>y</mi><mo>=</mo><msub><mi>W</mi><mn>2</mn></msub><mo stretchy="false">(</mo><mover><mover><mrow><msub><mi>W</mi><mn>1</mn></msub><mi>x</mi><mo>+</mo><msub><mi>b</mi><mn>1</mn></msub></mrow><mo stretchy="true">⏞</mo></mover><mtext>features</mtext></mover><mo stretchy="false">)</mo><mo>+</mo><msub><mi>b</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">y = W_2(\overbrace{W_1 x + b_1}^\text{features}) + b_2</annotation></semantics>y=W2​(W1​x+b1​​features​)+b2​[(2)](#JQNk2Df1tW "Link to this Equation")

Here, <semantics><mrow><msub><mi>W</mi><mn>1</mn></msub></mrow><annotation encoding="application/x-tex">W_1</annotation></semantics>W1​ is now an <semantics><mrow><mi>m</mi><mo>×</mo><mi>k</mi></mrow><annotation encoding="application/x-tex">m \times k</annotation></semantics>m×k matrix of weights, and the result of the matrix-vector multiplication and addition <semantics><mrow><msub><mi>W</mi><mn>1</mn></msub><mi>x</mi><mo>+</mo><msub><mi>b</mi><mn>1</mn></msub></mrow><annotation encoding="application/x-tex">W_1x + b_1</annotation></semantics>W1​x+b1​ is an <semantics><mrow><mi>m</mi></mrow><annotation encoding="application/x-tex">m</annotation></semantics>m-dimensional vector of features. We then apply linear regression with those features, using the weights in the vector <semantics><mrow><msub><mi>W</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">W_2</annotation></semantics>W2​ and intercept/bias in the scalar <semantics><mrow><msub><mi>b</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">b_2</annotation></semantics>b2​, to obtain <semantics><mrow><mi>y</mi></mrow><annotation encoding="application/x-tex">y</annotation></semantics>y.

Unfortunately, this doesn’t work because it reduces to a single layer of linear regression. Applying a bit of algebra, we can simplify the above equation to <semantics><mrow><mi>y</mi><mo>=</mo><mo fence="false" stretchy="true" minsize="1.2em" maxsize="1.2em">(</mo><msub><mi>W</mi><mn>2</mn></msub><msub><mi>W</mi><mn>1</mn></msub><mo fence="false" stretchy="true" minsize="1.2em" maxsize="1.2em">)</mo><mi>x</mi><mo>+</mo><mo fence="false" stretchy="true" minsize="1.2em" maxsize="1.2em">(</mo><msub><mi>W</mi><mn>2</mn></msub><msub><mi>b</mi><mn>1</mn></msub><mo>+</mo><msub><mi>b</mi><mn>2</mn></msub><mo fence="false" stretchy="true" minsize="1.2em" maxsize="1.2em">)</mo></mrow><annotation encoding="application/x-tex">y = \big(W_2W_1\big)x + \big(W_2b_1 + b_2\big)</annotation></semantics>y=(W2​W1​)x+(W2​b1​+b2​), which is just linear regression written in an unnecessarily complicated way.

In order to prevent the simplification to linear regression, we could apply a nonlinear function <semantics><mrow><mi>f</mi></mrow><annotation encoding="application/x-tex">f</annotation></semantics>f as part of computing the features:

<semantics><mrow><mi>y</mi><mo>=</mo><msub><mi>W</mi><mn>2</mn></msub><mover><mover><mrow><mi>f</mi><mo stretchy="false">(</mo><msub><mi>W</mi><mn>1</mn></msub><mi>x</mi><mo>+</mo><msub><mi>b</mi><mn>1</mn></msub><mo stretchy="false">)</mo></mrow><mo stretchy="true">⏞</mo></mover><mtext>features</mtext></mover><mo>+</mo><msub><mi>b</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">y = W_2 \overbrace{f(W_1 x + b_1)}^\text{features} + b_2</annotation></semantics>y=W2​f(W1​x+b1​)​features​+b2​[(3)](#V8VopBwHuC "Link to this Equation")

This is now the simplest possible neural network, which we call a **feed-forward** or **fully connected** network with one hidden layer (the so-called “hidden layer” is the result of the computation <semantics><mrow><mi>f</mi><mo stretchy="false">(</mo><msub><mi>W</mi><mn>1</mn></msub><mi>x</mi><mo>+</mo><msub><mi>b</mi><mn>1</mn></msub><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">f(W_1 x + b_1)</annotation></semantics>f(W1​x+b1​)).

The nonlinear function <semantics><mrow><mi>f</mi></mrow><annotation encoding="application/x-tex">f</annotation></semantics>f can be anything from a sigmoid or logistic function to the ReLU (restricted linear unit) function, <semantics><mrow><mi>f</mi><mo stretchy="false">(</mo><mi>z</mi><mo stretchy="false">)</mo><mo>=</mo><mi>max</mi><mo>⁡</mo><mo stretchy="false">(</mo><mn>0</mn><mo separator="true">,</mo><mi>z</mi><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">f(z) = \max(0, z)</annotation></semantics>f(z)=max(0,z).

In order to fit a linear regression model, we had to estimate good coefficients. In probabilistic terms, we did this using In order to fit a neural network, we have to estimate good weights <semantics><mrow><msub><mi>W</mi><mn>1</mn></msub><mo separator="true">,</mo><msub><mi>W</mi><mn>2</mn></msub><mo separator="true">,</mo><mo>…</mo></mrow><annotation encoding="application/x-tex">W_1, W_2, \ldots</annotation></semantics>W1​,W2​,… and biases <semantics><mrow><msub><mi>b</mi><mn>1</mn></msub><mo separator="true">,</mo><msub><mi>b</mi><mn>2</mn></msub><mo separator="true">,</mo><mi>l</mi><mi>d</mi><mi>o</mi><mi>t</mi><mi>s</mi></mrow><annotation encoding="application/x-tex">b_1, b_2, ldots</annotation></semantics>b1​,b2​,ldots.

To make our notation a little simpler, we’ll use <semantics><mrow><mi>θ</mi></mrow><annotation encoding="application/x-tex">\theta</annotation></semantics>θ to denote all our parameters: <semantics><mrow><mi>θ</mi><mo>=</mo><mo stretchy="false">(</mo><msub><mi>W</mi><mn>1</mn></msub><mo separator="true">,</mo><msub><mi>W</mi><mn>2</mn></msub><mo separator="true">,</mo><msub><mi>b</mi><mn>1</mn></msub><mo separator="true">,</mo><msub><mi>b</mi><mn>2</mn></msub><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">\theta = (W_1, W_2, b_1, b_2)</annotation></semantics>θ=(W1​,W2​,b1​,b2​). In order to find the best values of <semantics><mrow><mi>θ</mi></mrow><annotation encoding="application/x-tex">\theta</annotation></semantics>θ, we’ll define a loss function <semantics><mrow><mi mathvariant="normal">ℓ</mi><mo stretchy="false">(</mo><mi>θ</mi><mo separator="true">,</mo><mi>y</mi><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">\ell(\theta, y)</annotation></semantics>ℓ(θ,y) and then use stochastic gradient descent to minimize it.

## Empirical risk minimization[¶](#empirical-risk-minimization "Link to this Section")

We start by choosing a loss function. In general, the choice of loss function depends on the problem we’re solving, but two common choices are the squared error loss (also known as <semantics><mrow><msub><mi mathvariant="normal">ℓ</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">\ell_2</annotation></semantics>ℓ2​ loss) and the binary cross-entropy loss (BCE). Let’s consider the <semantics><mrow><msub><mi mathvariant="normal">ℓ</mi><mn>2</mn></msub></mrow><annotation encoding="application/x-tex">\ell_2</annotation></semantics>ℓ2​ loss:

This means that we must compute the gradient at every single iteration. So, anything we can do to compute gradients faster and more efficiently will make our entire optimization process faster and more efficient.

## Gradients and Backpropagation[¶](#gradients-and-backpropagation "Link to this Section")

Backpropagation is an algorithm for efficiently computing gradients by applying the chain rule in an order designed to avoid redundant computation. To see how it works, we’ll consider a very simple loss function of three variables. We’ll compute the gradient manually using the chain rule, and then we’ll see how backpropagation can do the same computation more efficiently.

### Backpropagation: an example[¶](#backpropagation-an-example "Link to this Section")

Instead of representing the computation as an algebraic expression, let’s express it as a computation graph. This is a visual representation of the mathematical expression.

Given specific numerical values for <semantics><mrow><mi>a</mi></mrow><annotation encoding="application/x-tex">a</annotation></semantics>a, <semantics><mrow><mi>b</mi></mrow><annotation encoding="application/x-tex">b</annotation></semantics>b, and <semantics><mrow><mi>c</mi></mrow><annotation encoding="application/x-tex">c</annotation></semantics>c, backpropagation is an efficient way to compute the loss and the gradient (i.e., all the partial derivatives), with no redundant computation.

We start by computing the loss itself. This involves just doing the computations specified by the graph, denoted by the blue numbers above the arrows:

![](../Images/7ebf128674b110b75005a4932a279339.png)

Next, let’s notice that when we did the calculations in the previous section to find the gradient, most of our expressions started at the loss, then, using the chain rule, computed partial derivatives with respect to things like <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q and <semantics><mrow><mi>r</mi></mrow><annotation encoding="application/x-tex">r</annotation></semantics>r. Let’s try to write these partial derivatives on the graph, and see if we can use them to keep working backwards.

1.  First, we’ll start with the easiest derivative, the derivative of the loss with respect to itself: <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>L</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>L</mi></mrow></mfrac></mrow><annotation encoding="application/x-tex">\frac{\partial L}{\partial L}</annotation></semantics>∂L∂L​. This is just 1!

2.  Next, we’ll compute the derivative of the loss with respect to <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q (top right branch of the graph). How did we get from <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q to <semantics><mrow><mi>L</mi></mrow><annotation encoding="application/x-tex">L</annotation></semantics>L? We multiplied by 16 (that is, for these specific numbers, <semantics><mrow><mi>L</mi><mo>=</mo><mn>16</mn><mi>q</mi></mrow><annotation encoding="application/x-tex">L = 16q</annotation></semantics>L=16q). So, the partial derivative of <semantics><mrow><mi>L</mi></mrow><annotation encoding="application/x-tex">L</annotation></semantics>L with respect to <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q is just 16.

3.  Continuing along the top part of the graph, now we can compute the derivative with respect to <semantics><mrow><mi>a</mi></mrow><annotation encoding="application/x-tex">a</annotation></semantics>a. How did we get from <semantics><mrow><mi>a</mi></mrow><annotation encoding="application/x-tex">a</annotation></semantics>a to <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q? We added 9 (that is, for these specific numbers, <semantics><mrow><mi>q</mi><mo>=</mo><mi>a</mi><mo>+</mo><mn>9</mn></mrow><annotation encoding="application/x-tex">q = a + 9</annotation></semantics>q=a+9). So, the partial derivative of <semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics>q with respect to <semantics><mrow><mi>a</mi></mrow><annotation encoding="application/x-tex">a</annotation></semantics>a is just 1\. But we’re trying to compute <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>L</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>a</mi></mrow></mfrac></mrow><annotation encoding="application/x-tex">\frac{\partial L}{\partial a}</annotation></semantics>∂a∂L​, not <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>q</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>a</mi></mrow></mfrac></mrow><annotation encoding="application/x-tex">\frac{\partial q}{\partial a}</annotation></semantics>∂a∂q​. So, we’ll take advantage of the chain rule and multiply by the “derivative so far”: that’s just <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>L</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>q</mi></mrow></mfrac></mrow><annotation encoding="application/x-tex">\frac{\partial L}{\partial q}</annotation></semantics>∂q∂L​ = 16\. So, our answer is <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>L</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>a</mi></mrow></mfrac><mo>=</mo><mn>1</mn><mo>⋅</mo><mn>16</mn><mo>=</mo><mn>16</mn></mrow><annotation encoding="application/x-tex">\frac{\partial L}{\partial a} = 1 \cdot 16 = 16</annotation></semantics>∂a∂L​=1⋅16=16.

4.  Next, we’ll look at the <semantics><mrow><mi>b</mi></mrow><annotation encoding="application/x-tex">b</annotation></semantics>b branch of the graph. From similar reasoning to above, the derivative at the output of the “multiply by three” block is just 16\. How do we use that to compute the derivative with respect to <semantics><mrow><mi>b</mi></mrow><annotation encoding="application/x-tex">b</annotation></semantics>b? To get from <semantics><mrow><mi>b</mi></mrow><annotation encoding="application/x-tex">b</annotation></semantics>b to that value, we multiplied by 3\. So, the corresponding term in the chain rule is 3\. We multiply that with what we have so far, 16, to get 48.

5.  Finally, let’s look at the <semantics><mrow><mi>c</mi></mrow><annotation encoding="application/x-tex">c</annotation></semantics>c branch at the bottom of the graph. We’ll start by computing the derivative with respect to <semantics><mrow><mi>r</mi></mrow><annotation encoding="application/x-tex">r</annotation></semantics>r. Similar to step 2 above, we multiplied <semantics><mrow><mi>r</mi></mrow><annotation encoding="application/x-tex">r</annotation></semantics>r by 11 to get <semantics><mrow><mi>L</mi></mrow><annotation encoding="application/x-tex">L</annotation></semantics>L, so that means that the derivative is 11.

6.  All we have left is to go through the “square” block. The derivative of its output with respect to its input is two times the input (in other words, <semantics><mrow><mfrac><mrow><mi mathvariant="normal">∂</mi><mi>r</mi></mrow><mrow><mi mathvariant="normal">∂</mi><mi>c</mi></mrow></mfrac><mo>=</mo><mn>2</mn><mi>c</mi></mrow><annotation encoding="application/x-tex">\frac{\partial r}{\partial c} = 2c</annotation></semantics>∂c∂r​=2c). Since the input was 4, that means our new term is 8, and our overall derivative on this branch is <semantics><mrow><mn>11</mn><mo>⋅</mo><mn>8</mn><mo>=</mo><mn>88</mn></mrow><annotation encoding="application/x-tex">11 \cdot 8 = 88</annotation></semantics>11⋅8=88.

Now we’re done! We’ve computed the derivatives, as shown in this completed graph with the backpropagation intermediate and final results in red below the arrows:

### Backpropagation[¶](#backpropagation "Link to this Section")

In general, all we need to successfully run backpropagation is the ability to differentiate every mathematical building block of our loss (don’t forget, the loss depends on the prediction). For every building block, we need to know how to compute the forward pass (the mathematical operation, like addition, multiplication, squaring, etc.) and the backward pass (multiplying by the derivative).
