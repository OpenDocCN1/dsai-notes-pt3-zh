## 对齐大语言模型：为什么以及是什么？

上一节我们介绍了本课程的目标，本节中我们来看看为什么需要对齐大语言模型，以及对齐的具体含义。

大语言模型的训练通常始于预训练阶段。模型通过预测互联网文本中的下一个词来学习语言模式，成为一个强大的“自动补全”工具。然而，这种基础模型在回答问题时，可能只是简单地续写它认为最可能的文本，而非提供有用、安全的答案。

![](img/796590a26924ecfbbbbf5d50bf86c36c_4.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_6.png)

为了将基础模型转变为有用的聊天模型，通常需要进行监督微调。在这个阶段，模型会学习数千个人工编写的“问题-答案”对。这能让模型学会以对话形式进行回应。

![](img/796590a26924ecfbbbbf5d50bf86c36c_8.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_10.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_12.png)

但监督微调后的模型仍然可能带有预训练数据中的偏见，或者不符合特定用户群体的偏好。对齐的目标就是进一步调整模型，使其行为更符合人类的期望和价值观。这不仅仅是关于内容安全或审查，更广泛地是关于让模型的行为与多样化的用户偏好保持一致。

![](img/796590a26924ecfbbbbf5d50bf86c36c_14.png)

## 传统方法：基于人类反馈的强化学习

在深入了解DPO之前，我们先来看看OpenAI开创的传统对齐方法——基于人类反馈的强化学习。

![](img/796590a26924ecfbbbbf5d50bf86c36c_16.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_18.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_20.png)

RLHF的流程通常包含三个主要步骤：
1.  **监督微调**：使用高质量的人工标注对话数据微调一个基础语言模型，得到一个初始的聊天模型。
2.  **训练奖励模型**：让聊天模型针对一系列提示生成多个回答，然后由人工标注员对这些回答进行排序。接着，训练一个独立的奖励模型，学习预测人类对某个回答的偏好评分。
3.  **强化学习优化**：使用PPO等强化学习算法，根据奖励模型给出的分数来优化聊天模型的参数，鼓励其生成能获得高奖励的回答。为了防止模型“钻空子”，优化目标中会加入一个KL散度惩罚项，约束新模型不要偏离初始模型太远。

![](img/796590a26924ecfbbbbf5d50bf86c36c_22.png)

虽然RLHF效果显著，但它也存在一些挑战：
*   **稳定性差**：强化学习训练过程通常不稳定，对超参数非常敏感。
*   **工程复杂**：需要同时维护和优化三个大型模型，对计算资源要求高。

![](img/796590a26924ecfbbbbf5d50bf86c36c_24.png)

## 直接偏好优化：一种更简单的替代方案

上一节我们介绍了RLHF的复杂性，本节中我们来看看DPO如何提供一种更简洁高效的解决方案。

![](img/796590a26924ecfbbbbf5d50bf86c36c_26.png)

DPO的核心思想是绕过显式的奖励模型训练和复杂的强化学习过程，直接使用偏好数据来优化语言模型。它通过一个巧妙推导出的损失函数，隐式地对齐了模型的偏好。

![](img/796590a26924ecfbbbbf5d50bf86c36c_28.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_30.png)

以下是DPO损失函数的关键组成部分：

**公式：DPO 损失函数**
```
L_DPO = -log σ( β * (log(π_θ(y_w | x) / π_ref(y_w | x)) - log(π_θ(y_l | x) / π_ref(y_l | x))) )
```
其中：
*   `σ` 是逻辑函数。
*   `β` 是一个控制偏离参考模型程度的超参数。
*   `π_θ` 是正在优化的策略模型。
*   `π_ref` 是固定的参考模型（通常是SFT后的模型）。
*   `x` 是提示。
*   `y_w` 是偏好回答。
*   `y_l` 是被拒绝的回答。

这个损失函数的目标是最大化偏好回答与被拒绝回答之间的对数概率差值。`β` 参数控制着模型在优化过程中可以偏离参考模型的程度。

![](img/796590a26924ecfbbbbf5d50bf86c36c_32.png)

DPO的优势非常明显：
*   **简单高效**：它只是一个可微分的损失函数，可以直接使用反向传播进行优化，无需强化学习。
*   **节省资源**：无需单独训练和存储奖励模型，只需一个语言模型和一个参考模型。
*   **训练稳定**：相比RLHF，DPO通常更容易收敛，超参数更少。

## 实践指南：监督微调

![](img/796590a26924ecfbbbbf5d50bf86c36c_34.png)

理论介绍完毕，现在让我们进入实践环节。对齐流程的第一步是进行监督微调，为后续的DPO训练准备一个高质量的初始聊天模型。

以下是进行SFT的关键步骤：

![](img/796590a26924ecfbbbbf5d50bf86c36c_44.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_46.png)

1.  **准备数据集**：寻找或构建一个高质量的对话数据集。数据集应包含“提示”和对应的“消息”（即多轮对话）。
2.  **应用聊天模板**：将原始对话消息格式化为模型能理解的特定格式。这通常涉及添加特殊的标记来区分系统提示、用户发言和助手发言。
    **代码示例：应用聊天模板**
    ```python
    from transformers import AutoTokenizer
    tokenizer = AutoTokenizer.from_pretrained(“your-model”)
    # messages 是一个包含角色和内容的字典列表
    formatted_text = tokenizer.apply_chat_template(messages, tokenize=False)
    ```
3.  **使用TRL进行训练**：利用Hugging Face的TRL库中的`SFTTrainer`可以轻松启动训练。你需要配置模型、分词器、训练参数（如学习率、批次大小）和数据。
4.  **超参数选择**：典型的学习率在`1e-5`到`5e-5`之间，并使用尽可能大的批次大小。

有了SFT模型后，我们就可以开始进行DPO对齐了。本节将详细介绍DPO的训练步骤和注意事项。

![](img/796590a26924ecfbbbbf5d50bf86c36c_61.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_63.png)

![](img/796590a26924ecfbbbbf5d50bf86c36c_65.png)

以下是执行DPO训练的核心流程：

![](img/796590a26924ecfbbbbf5d50bf86c36c_69.png)

1.  **准备偏好数据集**：数据集需要包含`prompt`、`chosen`和`rejected`三个字段。`chosen`是人类或AI评估者更偏好的回答。
2.  **格式化数据**：像SFT阶段一样，对`chosen`和`rejected`中的对话分别应用聊天模板进行格式化。
3.  **配置DPO训练器**：使用TRL库中的`DPOTrainer`。关键配置包括：
    *   `model`：你的SFT模型。
    *   `ref_model`：参考模型（通常与初始模型相同）。
    *   `beta`：最重要的超参数，建议在`0.01`到`0.5`之间尝试较小值。
    *   `learning_rate`：通常比SFT小得多，例如`5e-7`。
    *   `loss_type`：可选择`”sigmoid”`、`”ipo”`或`”kto”`。
4.  **开始训练**：调用`trainer.train()`开始优化过程。

在训练过程中，监控以下指标至关重要：
*   **DPO损失**：应稳步下降。
*   **准确率**：模型预测的`chosen`奖励高于`rejected`奖励的比例，应逐步上升。
*   **奖励边际**：`chosen`和`rejected`奖励之间的差值，应逐渐增大。

![](img/796590a26924ecfbbbbf5d50bf86c36c_71.png)

如果出现损失剧烈波动或准确率下降，通常意味着学习率过高，需要调低。

![](img/796590a26924ecfbbbbf5d50bf86c36c_73.png)

## 模型评估与前沿发展

![](img/796590a26924ecfbbbbf5d50bf86c36c_75.png)

模型训练完成后，我们需要评估其性能。同时，对齐技术本身也在快速发展，涌现出许多DPO的变体和改进方案。

以下是评估聊天模型的常用方法：

![](img/796590a26924ecfbbbbf5d50bf86c36c_77.png)

*   **MT-Bench**：一个多轮对话基准测试，使用GPT-4作为评判员，评估模型在推理、数学、创意等方面的能力。
*   **AlpacaEval**：评估模型输出相对于GPT-4 Turbo的胜率。
*   **人类评估**：最可靠的方法，邀请真实用户与模型交互并评价其回答质量。
*   **聊天机器人竞技场**：由LMSys维护，让不同模型匿名对战，由用户投票决定胜负。

![](img/796590a26924ecfbbbbf5d50bf86c36c_79.png)

DPO的成功也激发了更多研究。目前一些重要的扩展方向包括：
*   **IPO**：在DPO损失中加入正则化项，防止对偏好数据的过拟合。
*   **迭代DPO**：类似在线学习，不断用模型生成的新数据和奖励模型进行多轮DPO训练，持续提升模型。
*   **KTO**：只需“好”和“坏”的示例，而无需成对的偏好数据，大大降低了数据收集成本。
